# Local RAG Engineering — Phases 17–22

Use only when the **current numbered phase** has an accepted separate Codex preparation and active handoff. Phase 17 authorizes the **foundation only**; Phase 18 ingestion/OCR, Phase 19 QA, Phase 20 recommendations, Phase 21 expanded sources, and Phase 22 regression/reliability each require their own review/handoff. This skills document states shared guardrails, **not permission** to implement every item at once. See [RAG plan](../../../docs/implementation/rag-phase-plan.md). Preparation is not implementation authorization.

1. **Source of truth and scope:** existing owning Spring business module remains authoritative. Add only narrow public read-only projections where explicitly approved. Python never reads cross-domain JPA repositories or accepts arbitrary SQL. Preserve existing API envelope and Spring Modulith dependency constraints. The *proposed* initial Java `rag` leaf only depends on `vault`, `fiction`, and `film` public contracts; do not assume frozen changes are accepted. See P17-1.
2. **Fail-closed privacy:** do not index Private/NSFW, security-state, credentials or unknown-classification content. Only individually owner-approved NON_PRIVATE Fiction/Film fields and owner-approved external files enter the initial slice; `isNsfw=false` alone is **not** RAG permission. Unreviewed module fields, metadata and each unapproved Obsidian embedded child are denied. Enforce allowlists before extraction, vectorization, retrieval, recommendation, local judging and reports. Re-evaluate eligibility on deletion, trash, restore, classification changes and stale-version reads; synchronously deny and fence all grants/workers/index publication, then purge **all** transitive content-bearing derivatives, including cached prompts, answers/history, judge queues/evidence and parent transclusions; revoke overrides TTL. **At the source-finalization boundary, hold the owning `vault_entries` row guard (or Windows NTFS protected handle for a live external path) through Java COMMIT. Worker staging writes share DB-enforced lease-row locks with purge completion; an epoch-only fresh read is not sufficient.** See P17-2/P17-3.
3. **Offline:** no remote LLM/embedding/OCR calls, unsolicited downloads, telemetry or egress at runtime. Check transitive dependencies; bind internal services to loopback; bound memory/queues on the 8 GB VRAM desktop and verify offline operation in tests.
4. **Document adapters:** handle Markdown/Obsidian wikilinks, embeds, headings, frontmatter and block links; PDF layout/OCR and table structure; DOCX sections; spreadsheet sheet/cell mapping. Do not execute macros, formulas, Dataview/plugins, embedded instructions or external URL fetches. Refuse path escapes/symlinks/zip-slip and cyclic transclusion.
5. **Typed contracts:** version source selection, source hash, parser/chunker/model, evidence IDs, span locators, job state, retry/cancellation and error categories. Use Java-owned monotonic authorization epochs, source/field versions, immutable dependency manifests, guarded publishing and query/history/judge revalidation; Python uses a restricted PostgreSQL worker role (no business/security schema access, no DDL or active pointer/policy mutation). Maintain immutable index generation until validation and atomic swap; make reindex idempotent.
6. **Grounded QA/recommendation:** use bounded routing and evidence/citation checks, abstain when unsupported. Validate recommendation IDs against currently eligible existing catalog candidates, including all statuses by default. Never allow LLM-generated SQL or source mutation.
7. **Evaluation:** separate cheap required per-run safety/locator checks from async local LLM judging. Measure OCR text+table fidelity, retrieval recall, answer groundedness, recommendation validity/ranking, per-language regressions, latency and peak RAM/VRAM. Keep versioned gold datasets using fake/approved sanitized data only.
8. **Engineering quality:** apply `pragmatic-solid-design`, `reuse-and-consistency`, `design-pattern-selection`, `backend-testing` and `modular-monolith-architecture`. Use Strategy/Adapter only for real parser/runtime alternatives and explicit state for genuinely complex jobs. Prefer simple composable functions and narrow ports, not a speculative agent/plugin platform. Python code must use type hints, clear exception taxonomy, isolated pure transformations, pytest fixtures and code quality checks chosen by implementation handoff.
