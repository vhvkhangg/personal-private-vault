## Protected acquisition, capture and managed storage

The logical capture flow is `OWNER_APPROVED_FILE -> CAPTURING -> CAPTURED_TEMP -> SEALED_APPROVED -> INDEXING_ELIGIBLE -> SELECTED`, or safe discard/cleanup. These are target capture concepts, **not new indexing job states**. NO_CHANGE branches from CAPTURED_TEMP to guarded finish/disposal without R allocation.

1. Record finite explicit whole-file intent and expected authority, resource/deadline/cancel scope. Commit the existing single-operation exclusion and entire explicit capture-set reservations before bytes are read. Unknown admission acquires/sends nothing. No implicit child acquisition.
2. Prove allowed root/object/ancestor-to-stream binding and supported reparse/hard-link/writer/mapping semantics. Reject wrong root/object even with identical bytes, path traversal, network/unsupported/synchronized roots, device/alternate-stream paths, unsupported aliases and unproved binding. Read the acquired protected stream, not a later pathname reopen. Exclude incompatible pre-existing writers/maps and torn/ABA capture; timestamps, polling and before/after hashes alone are insufficient. Do not modify original files/ACLs as a shortcut.
3. Exclusive-create an opaque operation-owned protected temp, stream exact bytes and compute SHA-256/actual length under finite input/time/capacity/cancel limits. No decoding, parsing, OCR, normalization or repacking before hashing. The content is authorized but temp remains unsealed and inaccessible to ordinary indexing Python.
4. For Update, independently verify the selected ORIGINAL_BYTES snapshot and the complete NO_CHANGE predicate. Otherwise seal changed approved bytes at a unique no-overwrite immutable location with verified flush/durability/manifest. The same captured bytes may become R; no requirement deletes approved sealed originals before indexing. Partial/mismatched/unknown captures never promote.
5. Under short source-first guards bind the existing action to S/R/hash/length/provenance/epochs and exact finite child revision-vector closure. Discovery from approved content is not child consent or automatic closure expansion. Each new child requires its own finite capture/approval. Once capture/provenance/seal obligations and positive task/writer safety are known, original handles may release. No live-original claim follows.
6. Before one-use worker transfer, prove fresh snapshot protection/authority and complete closure union reservation. Capture/seal alone publishes nothing. Managed-object identity/integrity must remain protected through comparison/admission/use/physical finish. Prepare expensive hashing and I/O outside SQL guards; retained object protection plus fresh guarded metadata checks must bridge the interval.
7. Failed/cancelled/expired capture permits cleanup only, not renewal/resume/adoption. Prove task/writer death and known guarded outcome before safe exact release. Unknown SQL/process state retains exclusion/reservations. Reconcile owned temp/sealed orphans using validated durable identities and containment, never untrusted delete paths or hash-only adoption.

Java `rag` owns a configured private managed root outside source trees, static web roots, repository fixtures, shared TEMP and worker-writable scratch. Files use opaque S/R/attempt identities, not raw basenames/paths. Bytes remain outside PostgreSQL; logical authority stays in the existing RAG schema. Java creates/seals/deletes; the worker receives only exact approved bounded input over existing transfer, never arbitrary original/store paths or directory grants. Effective principal/handle/ACL isolation must be proved; same-user execution or secret paths do not prove it. No Media/S3/cloud owner, new module edge, driver, general queue/coordinator or synchronization daemon is introduced.

Establish finite source/closure/job/store-growth/cleanup bounds from representative measurements and owner review; low disk/resource failure cannot evict selected content or silently raise caps. Preserve Foundation 100-source/1 MiB/15-minute ceilings on old paths; command watchdog budgets are not user leases. Filesystem seal and short SQL metadata commits reconcile explicit pending/known states without a two-phase-commit platform.

## SHA-256 and guarded NO_CHANGE

Hash the exact complete protected original byte stream and compare **SHA-256 plus byte length** with independently verified selected ORIGINAL_BYTES R. Space/newline/CRLF/encoding/Unicode/container metadata changes are byte changes even if rendered text is equal. Rely on SHA-256 collision resistance, not mathematical impossibility; length is an additional check. BCrypt/Argon2id are not file-change algorithms here.

Keep original-byte digest/length, protected storage integrity, manifest/closure/scope digest, exact worker-input envelope digest and canonical actual producer/output digest distinct. None substitutes for original binding, owner/child approval, store protection, source/version/reset/incident history, producer identity, staged-output verification or trusted publication. Digests/provenance are sensitive, not public URLs/anonymous IDs.

All seven predicates MUST freshly hold for manual Update U targeting selected S/R1:

1. Authenticated finite whole-file Update intent and current expected S/selection/authority bind the authorized original/root/object/ancestors; no first-import hash shortcut, merge, same-path replacement or silent rebind.
2. A fresh finite protected coherent capture yields exact byte length L and SHA-256 H without parsing/normalizing/OCR/embedding.
3. Selected R1 is present, legitimate ORIGINAL_BYTES whose protected actual bytes independently verify to trusted L/H and equal the capture. Legacy projected, missing/purged/tampered or unverifiable storage denies.
4. Whole-file consent, reset/authorization/incident, consent-mode policy, retention, selected-R/sourceVersion and supplied expectations remain valid; no expiry/revoke/suspension/uncertain history/conflicting operation is bypassed.
5. Exact required dependency topology and independently authorized selected child S/R versions remain valid for the intended retained G, including remove/readd history, selection and child grants.
6. Relevant selection/pipeline/producer state and a legitimate current retained index remain valid. Missing/invalid G or requested pipeline reindex is not NO_CHANGE and does not justify a useless new file revision.
7. Existing source-first guards, exact reservations/attempt fence and protected managed objects serialize the final check against incident/consent/child/selection changes through actual finish. Missing or unknown proof denies success.

Valid equality preserves S/R/ordinal/sourceVersion/G/pointers/consent/reset/authorization/closure and runs no parser/OCR/chunker/embedding/worker. Only bounded operation/temp/receipt identity is allocated. Clean the comparison copy without deleting R1; original freshness remains UNVERIFIED. A changed approved capture creates R2, while pure explicit same-R reindex reads only R1 and publishes new G at C_P. Equal root bytes with changed child/edge/policy/vector require explicit authority/vector resolution or appropriate reindex/new immutable manifest, never in-place R1 edits. Unobserved edits to a child's original do not change an approved snapshot vector.

C_D-first denies finish; finish-first preserves its historical outcome and later C_D denies future use. A detached last SELECT is insufficient. Incident denial reports UNAVAILABLE with safe uncertainty reason, not actual REVOKED before known C_R. No retroactive retraction of lawful previously delivered bytes is promised.

Normal reserved revoke/privacy/reset/dependency mutations still return busy with **no requested change committed**; no auto-queue/retry. Complete a separate attempt-only stop-request transaction before source/process/control actions, positively stop launcher/sender/capture/worker/tree, drain/seal SQL writers and perform known safe atomic abort/cancel/release before owner retries actual revoke. Stop ACK/kill request/TTL/lost connection proves neither death nor revoke. Incident denial persists through failed/busy revoke, cancellation uncertainty, job terminal state and restart. C_R requires scoped transitive cleanup; mutation COMMIT alone proves no erasure.

After quiescence, explicit owner evidence review and source-guarded CAS may resolve demonstrably candidate-only/false-positive incidents. Retain monotonic incident history; never roll back epochs or clear committed revoke/reset into old consent/G, and never undo required purge. Old incidents do not automatically clear because this contract permits more content or hashes match.

Known rollback installs no new R selection/G. Unknown admission/C_D/C_R/C_P/C_N, abort or process/writer result retains exclusion/reservations and denies affected use until actual durable outcome is reconciled. A callback/marker/ACK is not physical C; lost response is not rollback. Restart loads incident/unresolved-inspection/control history first, proves task/process/SQL safety and never auto-resumes/copies/indexes/promotes. E1 late gates remain unchanged and waive no source/storage/producer proof.

## Retention, purge, backup and restore

Only authorized selected or legitimately referenced revisions/active-attempt content may remain. Superseded unneeded, failed, cancelled, orphan and comparison bytes require bounded verified cleanup. Revocation/removal overrides retention/references and purges whole approved files plus all actual transitive stage/published/retired chunks/vectors/mappings/temp/OCR/expanded derivatives. Original O is never a deletion target. Reports/logs/history retain safe codes/times/opaque control IDs, not source text/private paths/sensitive digests/locators; minimal reset/incident/anti-replay tombstones remain, not a content archive.

`PURGE_COMPLETE` is scoped to **APPLICATION_CONTROLLED_ACTIVE_COPIES**: targeted active SQL content and managed snapshot/temp/orphan files absent, no possible readers/writers or unauthorized references, required nonleaking control history retained. Failed controlled deletion/outage/open writer is pending and inaccessible. Safe release may precede erasure only after proved quiescence; it grants no reads.
