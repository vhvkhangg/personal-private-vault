## Context / baseline conflict

The accepted Phase 17 production path admits **one root** with a dependency closure, a version-2 lease/manifest, a **synthetic digest-only** worker receipt, and **one generation** tied to the job-wide lease manifest. It does **not** implement live external-file admission, real chunks/vectors, multiple independent roots, file-specific lifetime or partial result publication. Current source proof maps to Vault identity; external file identity must **not** be forged as a Vault ID. Phase 17 admission work/input limit and 15-minute execution lease are real bounded Foundation ceilings, not automatically suitable/approved Phase 18 document limits.

## Owner-approved D18-A contract — all eight clauses

1. **Scope / admission.** A manually admitted job has a finite ordered **set of distinct individually approved root identities**, with each root's exact independently authorized dependency closure. Reserve the **union** of all approved roots/closures atomically **before** any one-use input transfer. Reject any unapproved member, duplicate/conflicting identity/version, unsupported closure or incomplete reservation; do not represent unrelated file B as an artificial dependency of A. Exactly one active job, one supervised native worker and no automatic queue remain. Admission must not silently discard a root to meet limits.
2. **Source authority / guard order.** Existing domain/Vault sources retain their owning projections and Vault-owned version/reset/consent/reservations. New local external-file identity, version, field consent, revocation and durable reservations are **RAG-owned**, not synthetic Vault entries. For each mixed-source transaction, acquire **only the applicable subset** of this one deterministic **source-first** order, preserving the relative order of every Phase 17 guard: **(1)** short RAG graph barrier where needed; **(2)** sorted stable Vault source-state IDs; **(3)** sorted stable RAG-owned external-file source identity keys in canonical bytewise ascending order; **(4)** existing Vault lifecycle guards; **(5)** owner projection/assignment guards; **(6)** sorted RAG policy rows; **(7)** job/attempt; **(8)** generation/staging/run. External-file guards are the *only new ordering slot*; never acquire RAG policy/job/attempt rows first and then wait for source guards. Owner mutations take their applicable source-first subset; the worker retains its **attempt -> staging** path without owner-source locks. An **attempt-only stop-request** transaction must finish before any source/process/control action. Preserve the existing **NOWAIT** backstop for triggers already holding later-order target rows; never wait backwards. Keep SQL row locks short: no digest/hash, document read, OCR/model execution, HTTP transfer or process wait occurs under them. Mixed-source mutations must conflict while a matching durable reservation is live; unrelated sources remain editable. No second coordinator, global lock table, new Java module edge, reverse Vault dependency, worker business/Vault SQL or generic cross-module repository.
3. **Live NTFS R7 and exact input lifetime.** External live ingestion stays **disabled** until independent **R7** proof on native Windows NTFS: exact owner-approved path/root, ancestor/reparse/hard-link identity and writer/mapping restrictions; pinned file object/version, authorized bytes and metadata; guarded read without reopening an arbitrary worker path; identity/change/consent proof through trusted Java **physical final COMMIT**, including rollback/unknown-COMMIT handling and resource release. Bounded hash/read outside SQL row locks is permitted only when continuous source safety remains provable. Fail closed on unsupported filesystem/writer/mapping/handle semantics, even when a path looks identical. Immutable authorized copies are separate source identities, never a substitute claim that a live file is CURRENT. Java remains source-authority owner and sends only exact job-scoped approved input.
4. **Restricted staged content and model identity.** Version the existing job-scoped input/worker protocol and manifest (accept **legacy single-root Foundation version-2** unchanged). Add typed bounded per-file stage outcomes, normalized document elements, immutable chunks, embedding vectors, locators and generation-specific manifests in **RAG-owned** storage. Pin model **artifact hash, version, dimension, tokenizer, chunker, parser and OCR** identities with each generation. Stage under audited restricted PostgreSQL functions, actual `rag_worker` attempt provenance and the existing writer/attempt-row **through-staging-COMMIT** fence. Worker has no arbitrary path/SQL reads, DDL, policy mutation, publication, pointer or reservation-release rights. Private bodies, chunks, vectors, hashes, staging/temp/history require fresh read-deny, revoke and bounded deletion including transitive dependencies. Digest-only receipt is insufficient as a document index.
5. **Independent per-file generation lifetime.** Each eligible root has its own immutable actual root/child/field/version/consent/dependency manifest distinct from the job-wide reservation union. `CURRENT` is derived by fresh per-generation eligibility/selection/retention proof; unrelated B changing or revoked must **not** stale/purge A. A true dependent A must deny when child B changes, loses consent, fails staging or is revoked. Failed replacement of A does not install a new generation; previous A remains usable **only if independently CURRENT**. Reindex only on manual command; no silent stale-as-current fallback. Cleanup follows actual dependencies, not job-wide lease membership.
6. **One trusted atomic finalization.** After **positive** process/task-tree stop, writer drain/seal proof and stage verification, one Java-owned writable PostgreSQL **physical COMMIT** records every per-file outcome, installs **all valid successful generations or none**, terminalizes the attempt/job and releases the **exact entire reserved union**, in the existing E1/guard semantics. Failure of a file can be isolated only with valid independent proof; common worker, fence, process, policy, cancellation, SQL or commit failure publishes **nothing**. Known finish with >=1 successfully published root maps to existing terminal `COMPLETED` even if other roots fail; known finish with zero successes maps to `ABORTED`; known cancellation to `CANCELLED`; unknown SQL/process result remains **nonterminal** `RECOVERY_REQUIRED`, with reservations retained until reconciliation. `PARTIAL_SUCCESS` is **report-only** (derived), not a DB status. Unknown finish acknowledgment must be reconciled from durable state, never re-finalized blindly.
7. **Additive compatibility and measured limits.** Keep the accepted single-root Java/API and version-2 Foundation protocol working. Introduce only narrowly typed **batch admission, per-file report and versioned document worker/manifest** additions within existing `rag/api`, `rag/source`, module-local web and `ppv_rag` ownership; preserve shared `ApiResponse`/module advice contract. Add Flyway versions strictly **after the current tip V17 (start at V18)**, without rewriting V1–V17, frozen Schema v1 or existing ADRs. New logical [DBML](../database/phase-18-document-indexing.dbml) is additive and not runnable migration. Existing 100-node/1 MiB/15-minute Foundation limits remain effective on old paths; any Phase 18 limit change must be explicitly enumerated, bounded, measured on owner hardware and approved/reviewed before activation. CLI watchdog 1,200/2,100 seconds is **not** a user job deadline. No extra global slot, queue, scheduler, cross-module DB access, transport platform or model registry.
8. **Preserved restrictions.** Field-level explicit consent, Private/NSFW/unknown denial, source reset/revoke, verified exact child provenance, no write-back, manual reindex, positive native stop, SQL guard/COMMIT fences, E1 late gates, independent completed-index lifetime and Practical Local Offline remain mandatory. No Phase 19–22 retrieval/chat/judge, frontend, Ideaverse, cloud service, network-download or blanket containment-removal authorization.
