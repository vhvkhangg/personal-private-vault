## Blocking findings

1. **Medium — Concurrent category rename can leak a persistence exception.** In `LocationCategoryService.update` (lines 67–81), the duplicate-name precheck runs before `categoryRepository.save(category)`, but the entity is already managed and `save` does not flush its SQL update. A competing transaction can claim the same case-insensitive name; the unique-index failure then occurs during transaction commit, outside the `DataIntegrityViolationException` catch. The required stable `LocationCategoryNameAlreadyExistsException` is not guaranteed. Flush within the translation boundary, distinguish the name constraint from unrelated integrity failures, and add a PostgreSQL contention test for concurrent updates (including create-versus-update if that path is affected).
2. **Medium — Schedule reads can combine different committed versions.** `BusinessHoursService.getSchedule` (lines 104–119) reads `locations.business_hours_known` and interval rows in two statements under PostgreSQL's default `READ COMMITTED` isolation. A replacement can commit between them, yielding `known=false` with new intervals or `known=true` with cleared intervals. The writer lock serializes replacements with each other but does not make this read coherent. Read both from one consistent snapshot or coordinate the reader with the per-Location lock, then test the read/replacement interleaving.
3. **Medium — Raw persistence detail can escape the Image conflict boundary.** `ImageService.create` (lines 85–93) classifies constraints by message substrings and includes `ex.getMessage()` verbatim in its fallback domain exception. An unexpected integrity failure can expose SQL/Hibernate detail and private object-key data, contrary to the handoff's no-raw-persistence-error requirement. Translate known unique constraints via stable identifiers; use a non-sensitive generic fallback without embedding the persistence message. Test the fallback and object-key/checksum paths.
4. **Medium — Checksum uniqueness race lacks the required PostgreSQL test.** `MediaIntegrationTest` (lines 265–341) covers sequential checksum conflict and concurrent object-key conflict, but not concurrent `checksum_sha256` insertion. The active handoff explicitly requires Image unique-key races. Add a deterministic, observable PostgreSQL contention test for concurrent duplicate non-null checksums, asserting a stable Media-domain conflict and rollback of the losing Vault entry.
5. **Low — New internal packages lack `package-info.java`.** The Media and Location `internal.application`, `internal.domain`, and `internal.infrastructure.persistence` packages contain production code but no package descriptors. The active handoff and repository tree explicitly require meaningful package documentation. Add concise descriptors for these meaningful packages, without exposing internals as named interfaces.

The Phase 6 implementation otherwise remains in the approved Media/Location scope. The existing 448-test suite, module isolation checks, row-lock contention tests, derived image count, and unchanged Flyway V1 are useful evidence, but they do not close the findings above.
