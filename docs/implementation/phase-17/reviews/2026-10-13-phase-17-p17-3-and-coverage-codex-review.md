PostgreSQL documents transaction-lifetime row locks and savepoint release, and Spring distinguishes shared REQUIRED physical transactions from independent REQUIRES_NEW transactions. Future tests must also prevent a caught rollback-to-savepoint from silently discarding a guard while the outer gate continues. [PostgreSQL locking](https://www.postgresql.org/docs/18/explicit-locking.html), [Spring transaction propagation](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/tx-propagation.html).

Microsoft documents that omitted write/delete sharing rejects conflicting opens; omitted write sharing also rejects an existing writable mapping. This supports a feasible guarded-handle design, not a claim that a leaf handle alone proves the whole approved path. Test already-open writers/mappings, hard-link aliases, ancestor-directory rename/reparse/root replacement and handle closure/crash. Protect or reject any namespace component whose change would invalidate approval until COMMIT. The contract's unsafe-identity denial is mandatory; Java FileLock is not a substitute. [CreateFileW sharing and reparse semantics](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew), [directory handles](https://learn.microsoft.com/en-us/windows/win32/fileio/obtaining-a-handle-to-a-directory).
