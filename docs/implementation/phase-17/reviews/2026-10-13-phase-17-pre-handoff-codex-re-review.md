## Remaining blocker — P17-3: protect the last source check through the commit

References: [revocation contract](../revocation-and-derived-data.md), lines 7–12, 34–39 and R2/R7; [ownership contract](../integration-ownership-and-permissions.md), lines 8–9, 17–23 and 31–35; [architecture](../../../architecture/rag-architecture.md), lines 47–48 and 97–100. Current owning mutations: [FictionService.update](../../../../backend/src/main/java/com/vhvkhangg/personalprivatevault/fiction/internal/application/FictionService.java), line 151; [FilmService.update](../../../../backend/src/main/java/com/vhvkhangg/personalprivatevault/film/internal/application/FilmService.java), line 170; [VaultEntryService.moveToTrash](../../../../backend/src/main/java/com/vhvkhangg/personalprivatevault/vault/internal/application/entry/VaultEntryService.java), line 57.

The contract makes RAG-policy revocation and generation publication share a RAG authority row, but NSFW/content mutations belong to Fiction/Film and trash belongs to Vault. Those current owning transactions do not participate in a RAG lock/epoch. Post-commit events can be lost by the contract's own assumption. New projections are described as revision/classification proofs, without defining a guard whose lifetime reaches the RAG commit. Consequently, a plain fresh read plus a CAS of RAG-owned rows permits this interleaving:

| Order | Operation |
| --- | --- |
| 1 | RAG holds its policy lock and reads a current, non-NSFW source revision `r`, approval epoch `e`. |
| 2 | The owning module commits `isNsfw=true`, trash or a content change. Its notification is delayed/lost; RAG policy still has `e`. |
| 3 | RAG CAS checks its unchanged policy/lease rows and commits publication or answer/history from `r`. |

**This is an inference about the proposed integration, not an observed defect in the frozen backend or an implemented RAG service.** Another ordinary SELECT reduces the window but cannot protect the interval after that SELECT. A mutable external file has the analogous interval between the last successful identity/hash check and final commit unless the handle/snapshot contract defines stability through the gate. A version hash proves which bytes were checked, not that the live authority cannot change afterward. PostgreSQL row locks protect the rows actually locked; isolation-level names alone do not establish the selected application linearization point. [PostgreSQL locking](https://www.postgresql.org/docs/18/explicit-locking.html), [transaction isolation](https://www.postgresql.org/docs/18/transaction-iso.html).

Required preparation remediation:

1. Select and document a feasible owning-module guard/proof protocol and transaction composition that cover the authoritative domain state as well as RAG policy through each relevant publication/final-output commit. Use owning public APIs; do not introduce `fiction/film/vault -> rag` cycles or RAG repository access to those modules. Identify any required mutation-path coordination in the proposed approval delta. Clarify how Java's runtime connection/transaction boundary supplies the guarantee. A RAG-row-only lock, timestamp, snapshot isolation or after-commit notification is not sufficient by itself.
2. For external files, define the freshness/stability guarantee of safe handles or immutable authorized versions, its linearization point and its relationship to mutable path replacement and restrictive metadata. Do not describe a rehash-then-close check as stability through a later commit.
3. Make authority guards short: acquire/revalidate for the final bounded database/output gate, not around parsing, OCR, model inference, whole-corpus hashing or client delivery. State deterministic dependency/lock order and timeout/retry behavior. Consume real fresh source state, not an earlier cached JPA view. Preserve the existing rule that already-authorized/delivered output cannot be retroactively recalled.
4. Extend R2/R7 with barriers **after the last successful authoritative read/hash but before CAS/final commit**. Independently attempt Fiction/Film NSFW/content updates, Vault trash and same-path external-file replacement. Prove either a defined valid commit order or rejection, including lost notifications. Apply the same fence to worker lease/staging writes and purge completion: an old transaction must not recreate content after cleanup was declared complete. State when a response becomes irrevocably authorized; do not optimize by streaming unchecked model tokens before the gate.

The preparation must resolve this mechanism/contract gap; it need not implement or run future integration tests now. Existing P17-3 lifecycle requirements remain required and should not be weakened to pass the gate.

## End-to-end workflow assessment

| Stage | Assessment and concrete consequence |
| --- | --- |
| Selection / approval | Two-authority consent and individual source/field approval now fail closed. Directory additions and free-text file changes require approval; watchers propose candidates, not automatic permission. Batch enumeration and approval APIs should keep the initial workflow usable without starting Frontend. |
| Read / parse / OCR | Format adapters and table/layout preservation are appropriate. Native text first, selective OCR and explicit excluded-region handling avoid duplicate extraction. Bound expanded bytes/pages/cells and provenance mapping; unknown/hidden metadata cannot be silently admitted. |
| Normalize / chunk | Structural chunks and configurable parser budgets fit multilingual text/tables. Keep a versioned mapping to original spans; changing normalized text must not silently move citations. Repeat table headers as context without losing original cell locators. |
| Embed / stage | Separate worker computation from Java activation is sound. Bounded batches and immutable fingerprints support restart/reuse. Worker SQL must enforce current lease/job/source scope, not trust an arbitrary session variable or caller-supplied job ID. |
| Verify / publish | Atomic activation and side-by-side generations are appropriate. P17-3's remaining authority guard is blocking. Reuse of a previous eligible generation is permitted only when all current authority checks still pass. |
| Retrieve / rerank | Authorization must narrow the candidate relation before lexical/vector scoring and rank fusion. A shared approximate index with a WHERE filter can still involve excluded vectors; prefer scoped exact retrieval first and test scope invariance. Rerank a bounded candidate pool, not every chunk. |
| Typed facts / recommendations | Exact scoped counts/lookups should bypass generative retrieval stages. Recommendation must short-circuit an empty eligible pool, enforce all statuses and hard filters, and validate live catalog IDs. Initial reviews, ratings, tags, credits and Reference label fields are not automatically authorized by generic feature prose. |
| Generate / citations / return | Keep source content as data and disable write/arbitrary-tool routes. Buffer and validate the answer against the selected generation and current dependency proofs; retain the existing JSON ApiResponse contract. Resolvable citations alone do not prove a claim is entailed; numeric facts need exact checks/typed routes and semantic QA needs human-calibrated evaluation. |
| Judge / reports | Cheap per-run safety and locator checks remain synchronous; semantic judging stays asynchronous and cannot turn PENDING into PASS. Its queue consumes the same limited hardware; choose bounded scheduling/retention and preserve dependency-based denial/purge. |
| Revoke / recover | The artifact table and transitive dependency manifests now cover the important retained copies. Recover attempts from durable Java state, reject stale completions and reconcile orphans. Distinguish valid ongoing owner consent from an expired worker lease; do not require model rework or owner reapproval for every harmless transient failure. |

## Concrete improvements to carry into the bounded handoff

These are implementation-design/measurement constraints and improvements, not additional fabricated production defects. P17-3 is the remaining preparation blocker. No new provider, module, broker, agent or Frontend feature is authorized by the suggestions below.

1. **Capture one immutable query generation and separate artifact reuse from authorization.** Bind a query and every retrieval/model/citation hop to generation ID, embedding-model fingerprint/dimension, parser/normalizer/chunker configuration, exact approved field set, source/dependency revisions/epochs and session/grant scope. Same vector dimensions do not imply the same embedding space. The architecture's content-processing dedup key must not merge job/consent/session identities; an unchanged file in a new ad-hoc session needs fresh admission and independent output lifetime. Reuse deterministic authorized artifacts, then revalidate/rebind; never relabel a stale completion as a new job. Test query-versus-model/generation swap, changed field grants, reapproval of identical bytes and two independent session lifetimes.

2. **Start with eligible-relation exact vector search; earn ANN later.** Pgvector documents post-index filtering for approximate search. Thus generic `WHERE source_id IN (...)` plus global HNSW is not proof of the required pre-score scope or unchanged eligible recall/counts. Compare lexical-only, dense exact, hybrid and bounded reranking on the actual chunk count. If ANN is later worthwhile, require demonstrable scope isolation and quality evidence rather than adding per-file partitions upfront. Test that adding excluded/revoked/out-of-selection near-neighbor vectors cannot change eligible outputs or expose scores/counts. The application-policy consequence is an inference from the extension's behavior. [pgvector filtering](https://github.com/pgvector/pgvector#filtering).

3. **Batch freshness checks without caching permission indefinitely.** Measure bytes rehashed and gate time separately from retrieval/inference. Batch the two domain projections and Vault checks over bounded approved ID sets; deduplicate repeated embed dependencies within each gate. Avoid one Java/Python RPC per chunk or per field. An immutable snapshot may reuse parser/embedding work, but it does not excuse the final live-source fence. If the selected corpus cannot be safely verified within the budget, return a truthful bounded failure/coverage state; do not silently widen scope or present a partial count as an exact total. Per-file reapproval after content changes is an intentional operational cost of this initial privacy policy.

4. **Define one resource/deadline/scheduling profile before heavy workloads.** Fewer than 500 files is not a bound on PDF pages, expanded archives, spreadsheet cells, chunks or context tokens. Set configurable caps for these, total embed expansion, staging/temp disk, candidate/rerank batches, evidence/output tokens, queue depth, attempt count and end-to-end deadlines; select numeric values from local measurements. Share one bounded inference admission policy across OCR/embedding/reranking/generation/judging, not just one generation job while other GPU users run unconstrained. Keep control/cancellation RPCs responsive; prioritize interactive queries over ingest/judges and account for cold-load time, JVM/Postgres/Windows RAM and KV-cache headroom. Do not promise simultaneous model residency on the stated 8 GB VRAM/16 GB RAM desktop.

5. **Avoid redundant parser/model stages and constrain model behavior.** Extract native PDF text once; OCR only pages/regions needing it. Use one selected OCR/layout pipeline at runtime, comparing alternatives in benchmarks rather than always running both. Re-embed only changed approved chunk fingerprints with the same model/config; preserve table/header provenance. For the Qwen3 candidate, benchmark non-thinking operation and bounded output rather than copying the publisher's large-token examples; its published template enables thinking by default. BGE-M3 exposes dense/sparse/multi-vector modes and long-input capability, but the initial PostgreSQL lexical+dense design does not need all modes or maximum-length encoding. Enable extra complexity only for measured gains. [Qwen3 model card](https://huggingface.co/Qwen/Qwen3-4B), [BGE-M3 model card](https://huggingface.co/BAAI/bge-m3).

6. **Make evaluation independent enough to support promotion.** Separate development/tuning cases from a frozen held-out set, grouped by source to avoid near-duplicate leakage. Keep R1–R8 plus the new last-check barriers as deterministic security gates, separate from ML averages. Report language/format/status slices, no-answer false acceptance, citation entailment versus locator validity, OCR/table fidelity, recommendation hard-filter correctness and queue-inclusive latency. Calibrate local-judge scores against human labels; record seed/prompt/model/dataset fingerprints and failed/pending judge coverage. Batch or sample expensive judging only if that preserves the owner's required per-run reporting and is explicitly accepted; never infer security PASS from a judge score or omit failed cases from denominators.

7. **Verify offline startup as well as normal inference, and complete format fidelity fixtures.** Prefetch exact verified artifacts outside runtime; test warm and empty/missing caches with outbound IPv4/IPv6/DNS/proxy paths denied and only required local transports allowed. Missing models/language packs must fail locally, without a download attempt or SaaS fallback. Docling's remote-service opt-in and model-prefetch behavior are separate controls; disabling remote processing alone does not prevent first-use downloads. Add DOCX tracked/deleted/hidden text and comment fixtures, PDF reading-order/box rotation tests, legacy XLS conversion failures, and XLSX literal/formula/cached-value provenance. Do not present missing or unverifiably stale formula caches as exact calculated facts, and do not add formula execution. Specify offset units and normalization mapping for Vietnamese/Han, Java UTF-16 and Python code points. [Docling offline and resource options](https://docling-project.github.io/docling/usage/advanced_options/).

8. **Keep recovery and abstractions small and honest.** Use one Java-owned durable job state machine, bounded attempts/backoff and an explicit distinction between permanent parser/policy errors and transient service failures. Renew/reissue worker attempts only through fresh Java authorization under still-valid consent; source/field/hash/session changes still require the documented approvals. Test lost HTTP acknowledgement after commit, duplicate progress/completion, lease expiry, late staging writes, cancellation during native work, failed purge and rollback/model swap. If database restore is later supported, restored approvals/epochs must not be treated as fresh consent or allow replay of pre-restore grants; require an explicit recovery/renewal policy rather than only rehashing files. Prefer pure transforms, real format/runtime Adapters, a narrow orchestration Facade and simple state validation. Do not create a State class per enum, empty `rag/events`/NamedInterface packages, an index-provider framework, dual job engines or speculative Kafka/Celery/Redis infrastructure. The three detailed contracts should remain canonical with architecture/skill summaries linking to them rather than duplicating new rules everywhere.
