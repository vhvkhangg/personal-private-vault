# H1-F frontend/BFF session and OAuth preparation — selected prospective v0.4 contract

**Current D29 approval applies to the v0.4 bounded BFF session/CSRF scope, NOT a tested implementation. D26 Google Sign-In replaces the originally proposed password-login website entry.** H0 harness remains accepted and published. The detailed chosen session/security contract is [PH-05 v0.4](h1-f-bff-session-csrf-contract-v0.4.md), subject to Owner and independent Codex approval. It replaces earlier unselected SameSite/host/expiry/CSRF alternatives.

- **Authority:** Google supplies a **verified OIDC identity for sign-in only**, while **Spring issues PPV access JWT and opaque refresh** to an already bound singleton Owner. A separate Google Login Authentication backend capability is needed; Google Drive OAuth stays independent. One self-hosted Next Node BFF keeps Spring/Google tokens server-only; one opaque browser HttpOnly session cookie is the browser's PPV identity. See [Google login contract](h1-google-sign-in-owner-identity-contract-v0.5.md).
- **Local host/security selection:** `http://localhost:3000` Next to `http://localhost:8080` Spring, literal `localhost` only; `ppv_dev_sid`, HttpOnly, Lax, host-only, `Path=/`, local-only Secure=false exception. Future HTTPS uses a separately reviewed `__Host-ppv_sid`/Secure policy, not silently approved by H1.
- **Concurrency/lifecycle:** max 8 volatile sessions, anonymous 10/20-min idle/absolute, authenticated 30min idle/12h absolute, ID+CSRF rotation on login; per-session serialized backend refresh, generation-fenced logout/expiry and restart logout, no late refresh restoration. Local invalidation precedes best-effort backend revoke.
- **CSRF:** valid anonymous/authenticated session + exact Origin/Host/Fetch Metadata and server-bound CSRF token for **ordinary same-origin mutations** (Google login *start*/link, logout, actions); an external Google OIDC callback uses **one-time server-bound state/nonce/PKCE** rather than impossible same-origin Origin/header requirements. SameSite alone not sufficient; no anonymous identity adoption.
- **S1 cookie:** explicitly relay allowlisted backend `PPV_DRIVE_BINDING_{slot}` Set-Cookie from BFF authorization; browser must carry it on Spring's fixed `localhost:8080` callback path, returning fixed `text/plain`. A server-side BFF fetch is not proof cookie reached the browser.
- **Transfers:** preserve existing S2 50MiB/55MiB bounds, mandatory same action key/fingerprint/parent on unknown recovery, streaming download length/abort truth; no whole-file Next/JS buffering or unobservable “saved successfully” status. Use H1-B approved child/file/quota/search/preview endpoints only.
- **Versions:** dated *unverified, nonbinding candidate* Node 24.22.2 and Next 16.4.5, React 19.2.x, TypeScript 5.x, pnpm 10.x; select precise mutually compatible patch set, lockfile and advisory check in **separately authorized H1-F executable preparation**, not in this docs-only review. No installer/preview server now.

**Future independent tests, NOT_RUN:** pre-login CSRF; wrong/missing Origin/Host/token; fixation/expiry/logout; parallel refresh vs logout; restart; direct Route Handlers; cookie relay positive and wrong/expired/replaced negatives in real browser; upload unknown and download truncation; no browser token leak or shared cache; accessible UI/visual states relative to Owner approved images. The [v0.4 docket](owner-approval-docket-v0.4.md) is historical; Owner D29 accepted scope and D28 delegates derivatives. Keep main v0.3 approval binding. [Decisions](owner-decision-addendum-v0.5.md). `ACTIVE=NO_ACTIVE_HANDOFF`, no `frontend/`.


### Authentication correction required by D26

No secure **Google Sign-In** route, Owner subject binding or local onboarding flow exists in Spring `AuthController` at the verified main baseline. Do not implement the website's ordinary login by simply forwarding a Google ID token to an unprotected BFF endpoint or by treating a Drive slot connection as PPV authentication. Independent review must authorize [H1-AUTH](h1-google-sign-in-owner-identity-contract-v0.5.md) separately and reconcile its callback/session CSRF with the accepted local BFF contract. Do not remove established Spring password/refresh/revoke endpoints in this feature preparation.
