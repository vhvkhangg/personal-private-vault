## Selected transactions, provider validation and replay behavior

1. **Start/LINK gate:** require existing app_users.id=1 and immutable intended purpose. In a short transaction using AppUserRepository.findByIdForUpdate, enforce admission and persist attempt. LINK verifies the submitted password using the existing PasswordEncoder against the actual owner hash, not JWT age. Wrong-password event **must commit even when HTTP returns 401**; return a negative transactional result then map the error outside it, rather than throwing and rolling back the gate. Five failures in rolling 15 minutes block the next LINK attempt (even correct password) with 429 until expiry; no counter assumed on legacy `/auth/login`.
2. **Attempt claim:** validate state hash and binding-cookie hash, current purpose/owner/expiry, atomically PENDING→PROCESSING with random claim_epoch in one committed transaction. At most one claimant dispatches code exchange. Wrong proof does not grant/retarget an attempt. PROCESSING replay/restart fails closed; never reset to PENDING or automatically resend code. An in-flight duplicate must not steal the original claim. Expiry/failure invalidates its fence.
3. **Provider I/O outside all DB/owner locks:** use standard managed Spring OAuth2 Client/JOSE with an explicitly confidential client and **required S256 PKCE**, independent stored nonce, exact client/callback and fixed `openid email`, response_type=code. No offline/access_type or Drive scope, userinfo/profile fetch, silent refresh or raw Google-token persistence. Google client/token/JWKS objects are private to this path, never the PPV resource-server decoder.
4. **Identity/ticket finalization:** reacquire owner row, attempt under the captured claim and TTL; verify signed canonical issuer+sub and purpose. LINK inserts the immutable identity if absent; an existing identical binding succeeds without another identity; different subject conflicts, no upsert. LOGIN compares only the pre-existing binding; email or Drive slot never substitutes. Mark attempt COMPLETED and insert one random ticket hash/challenge/purpose/owner/60s expiry **in the same transaction**. Late/stale claim cannot publish identity/ticket. Clear encrypted PKCE on terminal transition; never save Google code/token.
5. **Handoff:** lookup bounded ticket hash then lock in canonical **owner→attempt→ticket** order; validate purpose/challenge/identity/TTL/status and constant-time verifier digest. Atomically PENDING→CONSUMED and call internal shared PPV issuance **inside that transaction**. No REQUIRES_NEW/provider I/O/independent commit. Persist hashed opaque refresh plus canonical HS256 access JWT; raw refresh only in the server response. Rollback on issuer/DB failure rolls back consumption and refresh row together. Concurrent/replayed redemption produces at most one pair; a committed lost HTTP reply is not reissued—start a fresh OIDC flow.

`SessionService.login` currently constructs its refresh row and JWT inline; extract only that body into `issueForVerifiedOwner(AppUser)` with mandatory existing transaction and singleton guard, call from password login and Google handoff. Reuse existing helpers/repository/clock/lifetimes/DTO. Do not create a second issuance algorithm, expose this through SessionOperations/HTTP, change JWT claims, rotate/revoke semantics or add a general auth refactor. Existing rotate remains authoritative for predecessor/successor lifecycle.

Fixed provider endpoints: `https://accounts.google.com/o/oauth2/v2/auth`, `https://oauth2.googleapis.com/token`, `https://www.googleapis.com/oauth2/v3/certs`. Client-secret POST is supported; no URL derived from a token/header/user. Private decoder validates RS256 signature, fixed issuer aliases `https://accounts.google.com`/`accounts.google.com` (canonicalize to HTTPS for stored binding), exact login-client audience membership and consistent azp (required for multiple audiences), exp/nbf/iat with explicitly tested **60s** skew and injected clock, exact stored nonce hash, nonblank unmodified sub <=255 chars. Never trim/casefold sub or bind by email. Reject unsupported alg, malformed/oversize token, invalid kid, jku/x5u/key-origin redirects, wrong nonce/client/issuer and signature/JWKS failure. No tokeninfo/introspection fallback.

Use finite default transport/cache: connect <=2s, **one overall <=10s token+JWKS budget**, at most one token exchange and one bounded JWKS fetch per claimed callback; no automatic code retry or redirect/cookie/proxy override. Bound token response/JWKS to 64 KiB, ID token to 16 KiB, <=8 accepted signing keys, JWKS cache TTL <=5 minutes, singleflight refresh and <=one refresh/60s on unknown-kid pressure. Fail closed on missing keys/cooldown; no stale-unbounded cache or repeated attacker-controlled key fetch. Force production TLS/hostname validation; controlled test endpoints do not certify live Google. Check/configure SDK defaults rather than assuming these bounds. Scope responses may omit scope or use Google's canonical email URI; qualify against the stored fixed request and known email alias, never permit extra Drive/offline scope or persist an unexpected Google refresh credential.

### Secret handling and resource/retention bounds

Dedicated 32-byte `PPV_GOOGLE_SIGNIN_TXN_KEY_FILE` stays outside Git and separate from Drive/JWT keys. JCA AES-256-GCM uses fresh 12-byte nonce/16-byte tag per record and versioned, unambiguous AAD binding attempt ID/purpose/owner/challenge/client. Only encrypted PKCE is persisted; nonce/state/browser binding and ticket/verifier proofs are hashes. Wrong key/tamper/AAD/nonce fails closed; no plaintext secrets, unsafe toString, raw exception cause or body/query/header logging. Real file ACL/backup/provisioning is operator proof later; fixture keys are synthetic.

Per installation: **4 outstanding protocol flows**, counting PENDING/PROCESSING attempts and unexpired pending tickets without double-counting their attempt; **20 admitted OIDC starts per rolling 60s**, counted under owner lock. LINK failure events enforce the separate approved 5/15-minute gate. Use the selected attempts table for durable counters; no fourth rate table. A small fixed process-wide admission/rate resource (no per-IP unbounded map) bounds 4 concurrent new endpoint requests, 2 provider exchanges and 32 callback/handoff submissions per minute per route; exhausted bounds return 429/503 without provider dispatch. Loopback address alone is not authentication.

Bound attempts and tickets to **1024 retained rows each**. On an operation, expire only expired flows and prune at most **32** terminal records older than **24h**, tickets before attempts, preserving active/unresolved proof and LINK failures inside their 15-minute window. A recovered PROCESSING attempt permits no code redispatch; if not yet expired it stays unusable until fail/expiry. Full capacity fails closed, not eviction of active proof. Identity is never pruned/unlinked. No scheduler, background workflow or audit payload table. All time comes from injectable Clock; PostgreSQL admission/claims and actual rollback/concurrency tests prove the limits, not just JVM counters.
