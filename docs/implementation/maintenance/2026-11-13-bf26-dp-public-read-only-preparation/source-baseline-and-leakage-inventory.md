These fields are intended PUBLIC on an **eligible** work, not a generic discovery right. Some IDs can reveal Owner interests as an inference, but the Owner explicitly approved that exposure for selected content works. Names are **not currently present** and would be additive contract changes, even though their source data is already available via named People/Group capabilities.

## Key security and correctness risks

1. **W1 already published** a Public Film POST; a policy-only document cannot revoke it. Revoke HTTP admission precisely; no mutation handler execution for live PUBLIC tokens, no cache/no stale JWT bypass. Keep `PROFILE_PRIVATE` create accepting the original broad request and response, including vendor JSON/Latin-1 compatibility.
2. **TOCTOU and snapshot:** `findPublic()` currently qualifies only minimal projections. A two-step `findPublic(id)` → `find(id)` or People lookup outside the snapshot could expose a newly NSFW/deleted/mismatched record. Qualify and materialize the entire approved DTO and scalar names within one reviewed owning-service `REQUIRES_NEW / REPEATABLE_READ` read-only boundary, or prove equivalent atomic read semantics.
3. **Indirect People privacy:** The permitted Fiction author/Film director name is specific to an already-qualified work. Public may not fetch `PersonView`, list people, infer arbitrary People existence via guessed IDs, retrieve CreatorGroup membership, or use hidden link/lookups.
4. **Static full DTO vs recursive graph:** The 18 JSON fields include IDs and strings, **not** linked PersonView or nested sensitive content objects. Do not automatically load or serialize nested entities, file bytes, Vault metadata, tags, or other module records.
5. **NSFW detail:** `isNsfw` is per Fiction/Film, not a global visibility column. The Owner does not want NSFW content publicly exposed; preserve 404 hidden-versus-absent and `no-store`. All other selected Public routes remain exact; no default-allow GET.
6. **B1/W1 contract migration:** Existing Public API schemas/tests expect six/seven fields; changing the return shapes is a **deliberate breaking expansion of Public data disclosure** requiring exact Owner frozen/HTTP OpenAPI approval and new test specimens. Not a silent DTO swap.
7. **Fail closed:** Downed People lookup or missing related name must have explicit wire semantics. Never fall back to sending a private People object or broadened 500 details. Decide null name/controlled fallback before implementation.
8. **Deployment evidence:** No new runtime tests, real Owner-data suitability, provider activation, Frontend acceptance or production deployment is established by this static inventory.
