## Proposed S2A request/response

**1.** `POST /api/v1/feed/sources/{sourceId}/refresh-rss` — authenticated Owner. Require existing source `type=RSS`, `enabled=true`, and valid `feed_url`; no user-supplied request-time target URL, body or arbitrary host override. Proposed new `RssFeedRefreshResponse` contains **truthful** fields: `sourceId`, `fetchedAt`, `parsedEntries`, `eligibleEntries`, `distinctArticleUrls`, `processedItems`. Do **not** report `inserted`, `updated` or current-rank counts without actual authoritative classification. Use existing root envelope/errors and Feed owner advice; distinguish missing 404, disabled/unsupported/unsafe source 422/502 as reviewed, already-running 409, upstream/time/limit errors 502/503, unauthenticated 401. Keep HN's pre-existing POST and its `FeedRefreshResponse` untouched. Actual exact wire/error code assignments are pre-handoff review targets, not accepted defaults.

**2.** `GET /api/v1/feed/radar/combined?limit=50` — authenticated Owner; default 50/max 100 proposed. Cached **HN + RSS**, deterministic SQL-bound `(published_at DESC, id DESC)`, same UTC rolling 24h bounds, only enabled sources and valid stored HTTP(S) article links. Optional sourceId filter is **deferred** in S2A; existing per-source item read remains available. Use compatible item shape with `sourceType` and `signalType`: for RSS `signalType=RSS_SOURCE_CACHE`, rank/HN story fields `null`, `signalCapturedAt` can be the persisted fetch time (label as fetched/cached, not an RSS rank); HN uses its existing provenance path. The existing `GET /api/v1/feed/radar` **continues HN-only** and must retain its exact response. A pure cached GET makes **zero provider HTTP requests**.

At baseline the S1 reviewed route inventory is **233** operations. With the proposed two additive routes, **235 is only a prospective expectation**; tests must verify the actual generated OpenAPI operation inventory, required security and accurate non-null/nullable schema. Do not claim this count was executed in preparation.

## Normalize only RSS 2.0 and Atom 1.0 into existing `NormalizedFeedItemInput`

- **Source:** stored `feed_sources.feed_url` for an enabled RSS source. Do not use `source_url`, returned feed self links, XML `xml:base`, alternate feeds or entry URLs as new network destinations.
- **RSS 2.0:** inside `rss/channel/item`, take nonblank `title`, absolute HTTP(S) `<link>`, optional `guid`, `pubDate`, plain-text author if present. GUID (`isPermaLink=false` included) is provenance only, **not** an automatic article URL. `<description>`/`content:encoded`/enclosures are not persisted as full text or fetched.
- **Atom 1.0:** `feed/entry`, `title`, absolute HTTP(S) `<link rel="alternate" href="...">` (omitted rel means alternate), `id` provenance, optional `published`; `updated` can be retained as explicitly labeled **update provenance** but never silently relabeled original publication. Atom relative `href`, unusual xml:base or extension-only links are explicitly excluded for initial MVP; record dropped-entry counts without the URL text. No XML content `src` dereference.
- **Entry validation:** skip missing title/article URL, invalid/overlong link, unsupported scheme, future publication timestamp, and invalid optional metadata as specified by parser policy; distinguish a valid feed containing no eligible entries from invalid XML/unsafe transport. The actual XML root must be RSS 2.0 or Atom 1.0; refuse unexpected dialect/root, DTD and external references.
- **Identity:** item `url` equals the **trimmed stored article link**, `externalId=null` to avoid cross-key ambiguity with existing generic ingest. For duplicate exact URLs within one fetch, select one representative: latest valid publication instant; tie: lexical source guid/Atom id (stable), then original document index. Keep one representative's bounded provenance. RSS guid/Atom id changes do **not** force article-URL identity replacement. Across refreshes, URL changes produce another row under existing frozen uniqueness. Preexisting rows with non-null external IDs are a required regression fixture.
- **Metadata:** a small typed JSON snapshot such as `feedFormat`, `feedEntryId` (bounded/truncated), `feedEntryUpdatedAt` (only when explicitly present), `rssCapturedAt` (post-fetch completion instant); no raw body, all entries, HTML, credentials or unsafe local data. Respect existing `FeedJsonSnapshot` deep-copy/immutability policy and column bounds. No fabricated RSS popularity or current ranking.
- **`publishedAt`:** only RSS pubDate / Atom published, if parseable and not future, otherwise `null`. `fetchedAt` is recorded **after successful provider fetch/parse**; missing publication items remain visible in `GET /sources/{id}/items` but cannot be included in the combined Radar's publication-time window.
- **Save to Inbox:** existing FeedItem save stores article URL and copies existing metadata; duplicate URL across sources still conflicts at SavedResource global URL hash. Do not normalize away query tracking parameters or silently merge unlike URL strings.

## Transaction and configuration race contract

1. Preflight read `id`, `enabled`, `type=RSS`, and exact stored `feedUrl` in a short no-transaction/readonly read. Acquire **shared admission** before network. Validate actual fetch target and perform all DNS/HTTPS/XML I/O outside any DB transaction.
2. Capture fetchedAt on successful complete response and bounded parse. Hand normalized candidates to a short `@Transactional(REQUIRED)` Feed-local finalizer with the existing `ingestFetch` call, **preserving existing item-then-source lock ordering** (avoid lock inversion and new prolonged lock).
3. In that **same physical transaction**, after generic ingest, use `findByIdForUpdate`+`entityManager.refresh` to assert authoritative source `enabled=true`, `type=RSS`, and the exact **same feed URL** that was actually fetched. If the configured URL/type/enabled changes during HTTP, **rollback rows and timestamps**, stable sanitized failure. Do not claim that a separate pre-ingest recheck closes the race.
4. No independent `REQUIRES_NEW` ingest or source timestamp commit. A test-only negative control must fail a shared-physical-transaction identity assertion for independent commits, as required by S1 FR-05 learnings; no production test callbacks.
5. Always release admission, including interruption, rate limit, invalid XML, source change and finalizer timeout. Source update remains allowed concurrently while HTTP waits, and cannot create stale RSS data after commit. S2B additionally checks scheduling authority under lock when invoked by the scheduler.

## Current/future source and Radar semantics

Existing feed sources can have metadata-only `feedUrl` of any scheme; S2A **does not** change source-create/source-update acceptance. Unsafe feed URLs are only rejected when initiating RSS fetching. Existing `FeedSourceType` remains the same. `GET /api/v1/feed/sources/due` remains a metadata-only bounded read, not a job trigger; scheduler S2B is separate. HN Radar remains HN-only; combined Radar does not pretend a rolling 24h time-window equals an externally sourced top-list or all Internet trends.
