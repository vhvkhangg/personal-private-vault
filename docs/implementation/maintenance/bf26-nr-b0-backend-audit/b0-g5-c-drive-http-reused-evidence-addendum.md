**Four-route denial.** Each S2:44 invocation applies one credential form (absent, malformed, fake Google token or expired) to POST root-folder, GET files, POST files and GET download. All four receive 401. No fake Drive calls and zero active spools are checked at the end of each four-request sequence. Credit for those side effects is at sequence scope. The sub=2 cases use synthetic signed JWTs without a valid persisted session. They do not isolate subject mismatch among admitted sessions. Genuine PUBLIC denial evidence remains separately scoped to V1-SEC.

**Callback boundaries.** Web:81 asserts anonymous non-GET callback POST/PUT/DELETE 401 with AUTHENTICATION_REQUIRED. The GET missing parameters returns 400 with exact generic text, text/plain compatibility, no-store and no-referrer. Web:242 reverses the cookie array with both cookies present, checks both callbacks succeed with the expected cookie-name prefix and exact text, and observes two fake exchanges and refreshes. The test loop uses the same callback order in both cases. Web:256 checks wrong/replaced/unknown proof cases return 400 without Set-Cookie, records zero exchanges before a valid callback, and records one exchange after success and replay rejection. Web:273 checks malformed parameters return 400, text/plain and no Set-Cookie before a valid callback, with zero earlier exchange. Web:287 checks the sampled provider denial returns exact generic text and a slot-cookie header prefix, with zero exchanges and subsequent replay rejection. The prefix assertion by itself supplies no cookie-deletion or other-slot state credit. Web:298 checks overlong state/code samples return 400 without Set-Cookie and with zero exchange.

**Limits.** Credit applies to the indicated checks in controlled fixtures. Status-only and partial field checks do not establish exact envelopes, persisted state beyond the observations, or universal redaction. HTTP disconnect status is separate from the causal effect of disconnect on an in-flight stream. [Wrong-slot download](b0-drive-download-reused-evidence-addendum.md) and [pre-body epoch guard](b0-drive-download-epoch-evidence-addendum.md) keep their reviewed scope. Wrong parent/slot on other groups, late revocation in real streaming, and combined ON generated OpenAPI are outside this batch. OS-level egress enforcement remains `NOT_VERIFIED`.
