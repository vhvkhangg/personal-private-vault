## Request and evidence path

Authenticated `POST /api/v1/rag/retrievals` starts one owned asynchronous sender. The synchronous facade validates input but rejects execution before admission because it cannot own a downstream evidence consumer. `POST /api/v1/rag/retrievals/{requestId}/cancel` requests stop and succeeds only after known terminal finish. An uncertain stop returns unavailable while retaining exclusion. Consumed request UUIDs cannot replay, including empty results.

The ingress filter bounds declared and streamed bodies to 64 KiB and uses the shared root ApiResponse error envelope. DTO and facade limits count Unicode code points: question 1–4,096; group/path 512; roster/collection labels 128. The pinned tokenizer additionally rejects more than 512 tokens. The entire root/child union must fit 100 distinct IDs. `topK` defaults to 5 (range 1–10). Excerpts total at most 12,000 code points and serialized responses at most 128 KiB; whole lower-ranked matches are dropped to meet bounds. A second local request receives busy without a queue; PostgreSQL enforces global exclusion.

Generic discovery pages coarse indexed candidates, canonically prepares each before counting CURRENT eligibility, and requests narrowing when the complete eligible union exceeds 100. Metadata and provenance scans are bounded at 10,000. Missing or unauthorized explicit selections never widen scope. Canon/noncanon groups are explicit labels tied to source IDs/revisions; no folder or basename inference occurs.

`RagRetrievalCurrentAuthority` reuses `RagSourceAuthority`: prepare the full dependency closure outside locks, preregister selected-revision inspections before snapshot bytes, verify immutable snapshots, then recheck exact prepared tuples under canonical graph/source/lease/generation guards at C_A and C_E. Newly changed or unregistered snapshot tuples fail before hashing. Prepared corpus payload is discarded; only authority metadata remains in proofs.

Canonical currentness also rechecks the exact committed inspection predicate **inside** `RagSourceAuthority.guardPrepared`, after ordered graph/external/source guards are held, for every external member of the prepared closure. An inspection that commits before the final guard denies CURRENT; if that currentness guard wins first, registration waits and the next currentness read is fenced. Earlier preflight checks cannot substitute for this guarded decision. Obsolete unrelated revisions and independent siblings do not deny the current source.

Provenance is validated in pages before PostgreSQL exact `<=>` ranking over admissible chunk IDs. Chunks must resolve to allowed actual contributors and exact immutable excerpts. ## Sender, native child and recovery

An owned virtual thread performs computation and serialization through the controller-supplied `RagRetrievalResponseDto.fromResponse` adapter and shared root envelope. Servlet `WriteListener` callbacks own nonblocking output: each bounded write/flush first checks readiness, and a not-ready callback returns to the container with its cursor preserved. No SQL transaction spans output. Stop prevents evidence output; late callbacks cannot replay it. A healthy unused output cursor can still carry the bounded non-evidence cancellation/error envelope. Finish requires zero active output callbacks, cleared serialized buffers, actual container `onComplete`, exact native tree stop and HTTP transport termination. An uncooperative active callback retains the buffer and durable exclusion. `complete()` alone is not proof. A shared monotonic five-second stop budget bounds cancellation waits; unresolved outcomes remain reserved for reconciliation without response replay.

For authenticated cancellation before C_E and response commitment, a healthy HTTP response returns **409 with the nonempty root `ApiResponse.error.code = RAG_RETRIEVAL_CANCELLED` envelope**, through the same readiness/WriteListener owner. Logical stop and transport failure are separate: cancellation intent is visible before its stop flag, and an error-only cursor may finish while the producer/native stop is still being joined; that does not release the reader. Output registration is serialized, but no monitor spans the callback's writes. An existing evidence cursor is stopped rather than restarted, and JSON is never appended to a committed response. A failed/unwritable transport follows bounded abort handling; an empty normally completed uncommitted error is not an approved substitute for the envelope. The separate cancellation endpoint retains its explicit DTO/root envelope.

A healthy, writable deadline before C_E likewise returns **503 with nonempty root `ApiResponse.error.code = RAG_QUERY_UNAVAILABLE`**. `onTimeout` records logical stop and reuses the error-only owner; `onError` records actual transport failure. The same Servlet readiness listener is registered before computation, without writing headers or bytes; the initial callback may arrive while there is no payload. This avoids first registering readiness during timeout handling, when the container still owes its initial callback. Once a single bounded payload is selected, its callback drains only ready bytes. Concurrent container/producer/timeout signals are coalesced by that listener into one cursor owner; no monitor spans writes and no new queue, timer or blocking fallback is introduced. Timeout handling drains ready error bytes and handles/completes the context before returning; unready, failed or committed evidence output follows bounded abort handling without appending/replaying JSON. Stop notification and `complete()` still do not authorize reader release without callback/container/native/transport quiescence and buffer disposal. No private container API or readiness-state override is used.

`RagQueryEmbeddingSupervisor` fences launch/cancel, binds PID plus exact Windows creation FILETIME durably before resume, and retains native/transport handles until positive stop. A false termination result is failure. `RagRetrievalControllerIdentity` captures controller FILETIME without changing frozen native process implementation. Existing reconciliation retries locally joined senders. Foreign recovery requires exact old-controller death and exact bound-child stop; live or unknown identity remains fenced.

`RagSnapshotInspections` owns snapshot inspection I/O and original-operation recovery within the existing reconciler. Per-file gates serialize byte checks outside SQL; reentrant checks share active-operation accounting. Recovery inventories bounded outstanding operations, proves local check/reader quiescence or exact foreign process death outside SQL, and verifies the captured original revision before classifying that original UUID. Recognized snapshot producers alone can be automatically reconciled. Missing descriptor/process proof or unknown producers remain unresolved. Startup rechecks the proven inventory under the runtime graph guard before adoption. Known incidents record INCIDENT_PENDING before exact source-denial CAS, deferring reserved-source C_D to the matching reader finisher. No fresh CLEAN UUID substitutes for an unresolved operation.

Selected and pending revisions receive distinct preregistered obligations before their respective byte checks. Known missing/corrupt bytes are recorded durably before a source-denial CAS/busy guard; failed SQL classification acknowledgements remain unknown rather than being invented as integrity incidents.

Query embedding uses the existing pinned CPU model/artifacts and Windows Job Object (2 GiB), explicit environment, loopback secret/nonce, no proxy/redirect/download and bounded HTTP reads. Readiness and result validate contract 1.0, reader/PID/nonce, model/tokenizer versions and hashes, 384 dimensions and actual process identity. Duplicate/extra JSON, invalid vectors and oversized streamed bodies/responses reject with sanitized diagnostics. Python query service has no database or staging capability.
