## 1. Request and Ingress Boundary

### Endpoints
- `POST /api/v1/rag/qa`: Submits a grounded Markdown QA question. Authenticated by Vault JWT. Validates question length (1–4,096 Unicode code points), retrieval mode (`GENERIC`), optional scope narrows, and conversation history entries.
- `POST /api/v1/rag/qa/{requestId}/cancel`: Requests cancellation of an in-flight QA request.

### Zero Leakage Enforced
- **Zero Question & Answer Leakage:** No question text, generated answer text, reasoning/thinking transcripts, or retrieved document chunk excerpts are logged to application logs or exposed in standard DTO `toString()` representations.
- `RagQaCommand`, `RagQaResponseDto`, `RagQaClaim`, `RagQaCitation`, and `RagQaHistoryEntry` implement customized, sanitized `toString()` methods that redact prompt, excerpt, and answer contents while preserving structural metadata (`requestId`, `mode`, `outcome`, counts).
- All operational and exception logging uses sanitized token identifiers, request UUIDs, and duration metrics.

### Single Durable Reader Exclusion
- QA operations acquire the same durable reader lease as retrieval via `rag.retrieval_readers`.
- At most one reader (retrieval or QA) can execute across the system concurrently.
- If a retrieval or QA query is already active, incoming requests receive immediate HTTP 409/429 rejection with error code `RAG_QUERY_BUSY`.
- On completion, timeout, cancellation, or failure, the reader lease is guaranteed to be released within a transactional quiescence block.
