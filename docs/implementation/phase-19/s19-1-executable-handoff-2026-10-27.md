| REMOVE / DEFER | ANN/hybrid/reranker, second DB, generic jobs/leases/providers, agents/hooks, judge/dashboard and rollout. Report a measured miss before proposing another retrieval stack. |

Enforce conservative **S19-1-specific** bounds and measure them at handback: question 1–4,096 Unicode code points and at most 512 pinned-tokenizer tokens; JSON body at most 64 KiB; at most 100 distinct IDs in the complete reader root/child union; topK default 5, range 1–10; at most 12,000 excerpt code points overall and 128 KiB serialized body; group/path labels at most 512 code points and roster version/collection labels at most 128. Reject duplicates/conflicting revisions and oversize requests; no silent question/roster truncation. Return whole verified chunk/spans, dropping lower-ranked candidates to meet the response bound rather than fabricating shortened locators.

The 100-ID reader limit is a deliberate **query** bound enabling reuse of V18's exact single-token reservation. It is not an inherited ingestion-job requirement or an assumption that 203 inventoried files are imported. Generic metadata discovery reads at most cap+1 distinct IDs; if eligible roots plus dependencies exceed the cap, return `RAG_QUERY_SCOPE_LIMIT` and require narrower selection, never an arbitrary first page. Dependencies count even when excluded from evidence.

Use a 120-second overall retrieval/sender budget including embedding startup, then a bounded stop/cleanup attempt up to 5 seconds. Retain existing short SQL limits (at most 10 seconds per transaction) and graph/closure bounds. Query child: CPU-only, 4 inference threads, 2 GiB native Job Object memory cap, one process; measure peak/startup/total time on Windows. This is not a generator resource profile or performance certification. Deadline initiates stop, not release. Report measured mandatory failures before raising bounds/changing model. Command-watchdog time is separate from request lifetime.

## API / citation contract

Add exactly two authenticated RAG-local routes using existing root `ApiResponse`/`ApiResponses`, strict unknown-field validation, bearer security and explicit OpenAPI examples. No authentication/JWT code change or public security exception.

1. **`POST /api/v1/rag/retrievals`**, operationId `retrieveRagMarkdownEvidence`. `RagRetrievalRequest`: caller-generated opaque UUID `requestId`, `question`, `mode` (`GENERIC`, `IDEAVERSE_CANON`, `IDEAVERSE_NONCANON`), optional `selection`, `rosterVersion`, `collectionId` and `topK`. Selection entries bind numeric RAG `sourceId` and UUID `selectedRevisionId`; Ideaverse entries also include Owner-declared group and relative display path. UUID identifies one reader so caller can cancel without waiting; reuse/replay never starts new work or replays cached evidence.
2. **`POST /api/v1/rag/retrievals/{requestId}/cancel`**, operationId `cancelRagMarkdownRetrieval`. Commits reader stop intent and requests bounded quiescence/finish only; no source mutation. Success reports actual terminal disposition; repeated cancel of known terminal reader is idempotent. Unknown ID: safe 404. Unknown stop/finish: unavailable/recovery-required, never successful cancellation. No public polling/history/file-content route.

Illustrative generic request (not real source IDs):

```json
{"requestId":"13f7f818-0cd0-4a74-b523-2b4b8b6d5bbf","question":"Thuộc tính này được mô tả ở đâu?","mode":"GENERIC","selection":[{"sourceId":41,"selectedRevisionId":"27f9879f-6b50-49ad-a713-b7527cc485a3"}],"topK":5}
```

Omitted generic selection means all eligible indexed Markdown within the bound. Explicit selection is the evidence allowlist, not implicit child expansion. Both Ideaverse modes require a nonempty versioned collection-bound Owner declaration: classification is authenticated Owner metadata, not filesystem authority/server signature. Canon uses only listed `IDEAVERSE_CORE` contributors. Noncanon mode explicitly opts into its listed eligible CORE/NONCORE entries with accurate per-match labels. Missing/stale/ambiguous roster or absolute/drive/URI/traversal display path denies; no generic fallback or server-managed group persistence.

Success `data`: `RagRetrievalResponse` with requestId, outcome (`EVIDENCE`/`NO_EVIDENCE`) and bounded matches. Match: response-local citation key, exact excerpt, contributing numeric sourceId, external fileSourceId, selected revisionId, public generationId, approved display name, verified heading/locator and applicable group. Distinguish public generation UUID from numeric DB row ID. Returned evidence includes `freshnessBasis=RAG_SNAPSHOT`, `snapshotIndexState=SNAPSHOT_CURRENT`, `originalFreshness=UNVERIFIED`; no liveCurrent, internal paths, hidden candidates/totals/dependency aliases or generated answer/confidence. A resolvable citation means identity/locator/excerpt check against the protected selected snapshot; no new file-serving route.

Empty: `NO_EVIDENCE`, matches=[]; similarity ranks candidates, not factual support. Omit public distance scores. Use `Cache-Control: no-store`; never put question in URLs, DTO toString, operational logs or traces. No client-receipt/ACK promise.

### Admission, evidence filtering and exact ranking

Resolve bounded source/generation **metadata** before C_A; do not load/rank published chunk content or expose candidates yet. Reject non-external/unsupported sources. Build immutable complete actual root/child revision/version/epoch/reset/policy/generation closure; verify grants even for dependencies excluded from evidence. Preregister authority-sensitive inspection before managed-snapshot verification. Bridge outside-lock hashing with protected immutable-object identity and guarded proof recheck; clean inspection resolves only its exact tuple, incidents/unknowns remain durable.

C_A order: graph guard → sorted external/source guards → reader/inspection/generation state. Recheck current runtime, completed/sealed indexing attempt, active PUBLISHED generation, pipeline identity, selected revision/manifest digest and full closure authority; atomically record reader and reserve exact union with a unique token.
