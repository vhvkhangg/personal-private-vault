**Status:** `P19-OD-01 OPTION A OWNER_APPROVED (DESIGN ONLY) / P19-PR-01 HIGH STILL OPEN UNTIL CODEX RE-REVIEW / NOT IMPLEMENTED`; **not** an applied migration, deployed capability or amendment to frozen P17/P18. This is a bounded response to independent P19-PR-01 (HIGH) and P19-PR-03 (MEDIUM). [P19 scope](owner-decisions-and-scope.md), [original independent review](reviews/2026-10-27-phase-19-independent-pre-handoff-review.md), [P17 revocation](../phase-17/revocation-and-derived-data.md#3-published-reads-and-later-capabilities) and [ADR-0022](../../adr/0022-phase-18-immutable-snapshot-whole-file-consent-no-change.md) control. The final mechanism must be independently checked against real source/DB paths before an executable handoff.

## Selected *prospective* mechanism: one durable, source-scoped Q&A consumption barrier

The existing `RagGenerationState.state()` is a **point-in-time** proof, not a model-consumer lease; its transaction ends before inference. Existing `SourceIndexReservations` and `rag.external_file_reserve/release` protect **indexing** and may be reusable as primitives, but no accepted source proves they can be used unchanged as a Q&A read lifetime. Owner-approved P19-OD-01 selects **one bounded durable active-reader record, with the source/child exclusion integrated into existing ordered authority/guard paths**, rather than independent polling, a long-lived SQL transaction, an optimistic last-check, client ACK, TTL-as-permission, or new generic job/lease infrastructure.

- **Admission and linearization `C_A`:** after Owner authentication and bounded source-ID selection, Java constructs the *complete contributing provenance closure*, including every root, transcluded child, selected immutable revision, authorization epoch/reset/policy, generation and allowed evidence scope. Under the same authoritative sorted source/policy/graph guards used by existing mutations, **atomically COMMIT** (a) validated `CURRENT` generation and per-source/child entitlement and (b) an active Q&A consumption exclusion tied to an opaque request identity. The record survives an application crash. Any overlap with an existing indexing reservation or incompatible active writer fails closed; serialize Q&A requests if necessary for this personal app. No unapproved chunk is read, count/rank exposed or dispatched before `C_A`. Do not rely on a stale `PUBLISHED` flag. Q&A has no source mutation or publication privileges.
- **During inference:** the durable exclusion spans database retrieval, Java-to-local-process context transfer, embeddings, generation and all output buffers. Normal source-affecting edits/revoke/privacy/reset/selected-R changes, dependency changes and purge require the same ordered guards, and receive the existing no-change `409 BUSY` while an incompatible reader is admitted. A **mandatory authority/integrity incident is different**: it is never dropped as an ordinary BUSY mutation. Its trusted observer must durably register an incident obligation under those same short guards (`C_I`, below). This registration is **not** physical denial `C_D`, does not release an exclusion and does not bypass ordinary policy/consent mutation rules. If the incident wins before guarded `EMITTING`, the reader becomes non-emittable; if `EMITTING` wins first, the current already-authorized server-side emission may finish **without C_D interleaving**, while the committed pending incident blocks fresh admissions. See the precise [incident handoff](#durable-incident-handoff-at-emission-p19-pr-01).
- **Final authorization and actual response emission (`C_E`):** non-streamed output is withheld inside trusted Java until complete statement/locator evidence and all contributing authorities have been validated under the existing exclusion. A **short guarded COMMIT** transitions the reader to `EMITTING` only after checking it has no pending incident, unresolved inspection or stop/deny intent; this transition is the ordering point with `C_I`, **before** the first response-body byte. The exclusion remains through the actual server-side write/flush lifecycle, **not** merely a controller return or a DTO serialization callback. No SQL lock spans write/flush or inference. Already emitted bytes cannot be recalled; network buffering or client receipt is not treated as proof. After positively verified terminal emission (or verified no-further-emission failure), process/sender quiescence and context/KV disposal, Java may attempt guarded reader finish (`C_RL`) **only through the conditional incident-finisher rules below**. An ordinary no-incident finish may atomically mark `TERMINAL` and release; an incident-bearing finish may release only together with, or after a proven still-effective guarded denial barrier. No separate release-then-deny interval exists.
- **Abort/cancel/disconnect:** first durably register stop/deny intent and halt future emission if it has not started. Positively stop model request processing and actual HTTP sender; discard request-local model state and verify owned worker death if per-request context disposal cannot be proven. If an incident is pending, abort still uses the same incident finisher; ordinary cancellation must not clear or roll back the pending incident. Failed sender/worker stop is `RECOVERY_REQUIRED` with the exclusion **and incident obligation** retained; a timeout, disconnect or kill request alone is not quiescence or release proof.
- **Restart, unknown outcome, restore:** a durable nonterminal reader and/or pending incident blocks overlapping new admission; boot reconciliation must inspect both before deciding any release. Prove all prior model context, sender, process, transport and SQL writers stopped and reconcile their actual durable states; never resend a possibly emitted response. Any unknown `C_I`, `C_D` or `C_RL` COMMIT/rollback is reconciled by read-back under the same guards and exact incident/reader identity, **not** assumed successful or safely absent. Where a producer's incident-record operation failed/has unknown outcome, its durably preregistered inspection/recovery obligation and reader exclusion must not be cleared simply because no final incident row can be seen. If necessary, remain `RECOVERY_REQUIRED` until evidence proves a safe source disposition; neither TTL nor process exit auto-releases. Shared CPU model weights may be reused only without carrying a prior request's prompt/KV state; otherwise terminate its process per request.
- **Source change priority:** compare both commit orders. If `C_A` wins, mutation returns existing busy or uses authorized cancel-first/quiescence before real `C_R`; if source mutation/deny fence wins, `C_A` fails. A child revocation invalidates its parent as appropriate. Reapproval must not revive an old reader/context: source epoch/reset and selected-R identity are bound and freshly checked, with no ABA based on equal text. Generic Q&A remains scoped only to eligible approved Markdown.

### Durable incident handoff at emission (P19-PR-01)

**One authority and one ordering slot, not a second queue.** This is a **prospective** specialization of the approved P19-OD-01 durable reader plus ADR-0022's trusted-Java deny-only incident/`INSPECTION_UNRESOLVED` semantics. Reuse an existing committed incident state if its real schema and guards prove equivalent; otherwise only a **minimal RAG-owned pending-incident field/record associated with the affected reader and exact source/revision closure** is in scope. Any schema/function delta is to be identified at handoff after independent pre-handoff acceptance and separately authorized for implementation. Do not claim the currently installed indexing reservation or `RagRecoveryService` already provides this protocol.

| Event/commit | Responsible owner and short guarded atomic effect | Consequence / ordered next step |
| --- | --- | --- |
| **Authority-sensitive inspection starts** | Trusted Java **inspection/reconciliation producer** registers a scoped durable `INSPECTION_UNRESOLVED` / equivalent existing pre-inspection recovery obligation **before** reading/inspecting evidence that could discover a source-level incident, as required by ADR-0022. No raw content persisted. | A crash before classification cannot make an unknown inspection silently disappear. Independent ordinary parsing is not elevated to an incident. |
| **`C_I`: incident observed / intent registered** | The same trusted Java **incident producer** uses a short source-first transaction (graph where needed → sorted affected root/child source guards → reader/incident state) to **COMMIT `INCIDENT_PENDING`** bound to a unique incident ID, exact S/R, revision/epoch and all truly dependent active reader/generation identities. Set a monotonic `deny_new_admission` predicate and a reader stop/no-emission flag if the reader has not entered `EMITTING`. This is an incident *intent/inspection fence*, **NOT `C_D`**, not a normal revoke, not a reservation release. | Overlapping Q&A/index admissions, generation selection, count/rank/citation disclosure, source promotion and any incompatible cleanup are refused while pending. Never return `409 BUSY` and forget a genuine incident. Multiple observations remain idempotently pending until individually resolved; unknown scope fences the bounded potentially affected closure. |
| **Incident wins before `C_E`** | `C_I` commits while reader is `ADMITTED`/`CONSUMING`/pre-emission. The `C_E` short guarded transition must observe the pending marker and **fail**; no body bytes can begin. | Cancel/quiesce the affected reader and handle authoritative `C_D` using the guarded finisher. `C_I` alone is not falsely reported as revoked. |
| **`C_E` wins before incident** | Trusted Java response writer performs the short guarded **`EMITTING` COMMIT before first byte**. Subsequent incident producer **commits `C_I` during emission** under the same guards without changing source consent/reset/selection or executing premature `C_D`. | Existing writer may finish already-authorized server-side emission; its reader exclusion and pending incident survive throughout. New admissions are denied from the `C_I` COMMIT. No SQL transaction or source lock is held while waiting for sender, HTTP or model process. |
| **`C_D` + `C_RL`: guarded incident finish** | After **positive** sender completion or proved no-further-emission, worker/context quiescence and required inspection evidence, a trusted Java **reader/incident finisher** holds the same short ordered guards, verifies immutable incident/reader closure and applies the real scoped **authoritative deny `C_D` and terminal reader/exclusion release `C_RL` in one physical COMMIT**. Required generation invalidation/purge denial state must be established by that COMMIT; slower safe erasure may follow only after quiescence under existing purge rules. If `C_D` is durably committed separately first, a still-effective durable denial/admission fence must remain under the same guards until later guarded `C_RL` (no interleaving window). | Source/child and dependent generations remain non-readable after release; another reader/index admission can never enter between terminal release and actual denial. No broad policy bypass, consent renewal or premature purge. |
| **Failed/unknown incident or finisher transaction** | No independent `release()` callback, no blind retry, no timeout-based cleanup. Mark or retain `RECOVERY_REQUIRED` together with the exclusion and unresolved `C_I`/`C_D` obligation; reconcile actual PostgreSQL COMMIT/rollback by the immutable IDs, applicable guard records, and inspection history. | A missing ACK, a zero-row update, a process death or no visible final incident row is **not** proof of no incident. Until reconciled, no overlapping admission/answer/cleanup completion. Recovery may finish the same guarded operation after true quiescence and verified authority, not create a fresh untracked reader. |

**Producer/finisher coordination and lost-intent edge:** an incident-observing path active during emission must complete or durably register its `C_I` obligation **before** the reader finisher can certify clean completion. Every authority-sensitive inspection is preregistered durably, and the finisher checks pending **and unresolved inspection/incident operations** under the source guards, not just an in-memory callback counter or the reader's own state. If `C_RL` and an independent observation overlap, the same sorted guard determines the physical order: an already registered/unresolved inspection prevents clean release, and a later independent inspection must persist its own source-scoped `INSPECTION_UNRESOLVED` before inspecting. An observed-but-unrecorded incident is a recovery obligation, never a successful silent no-op. The reader does not have to hold SQL guards while waiting for that producer; unknown producer progress causes fail-closed `RECOVERY_REQUIRED` rather than optimistic release. Stop or timeout cannot discard a committed incident obligation.

**Existing-path compatibility requirement:** existing `RagRecoveryService.reconcileSnapshots` performs a denial update only for `reserved_by IS NULL`; therefore an active Q&A reservation may make that update affect **zero rows**. Do not call that path, treat the zero-row result as a successful `C_D`, release first to satisfy its predicate, or retry outside reader guards. The executable handoff must show a narrow **trusted-Java incident-finisher / guarded SQL CAS** capable of the atomic `C_D`+`C_RL` effect for the specific matching reader/reservation (or equivalent durable denial fence across separate commits). Integrate `RagSourceService` source-policy/dependency mutation backstops, `RagPurgeService` generation invalidation/erasure and `RagRecoveryService` incident reconciliation with the *same* read-admission predicate and finisher. Protect exact transcluded-child and dependent-generation closures; ordinary Owner edits/revokes still return unchanged `409 BUSY` without granting a general mutation bypass. Any need to weaken ADR-0022 denial or frozen mutation semantics, or to introduce a larger state service, is a **new Owner decision**—not authorized by this dossier.

**Minimal durable state:** use an opaque Q&A reader identity, source-exclusion token, immutable root+child S/R/version/epoch/reset and generation closure, finite state/worker/sender identity, **verified** context/stop/emission evidence, and any matching `INCIDENT_PENDING`/`INSPECTION_UNRESOLVED` ID + affected closure/producer identity/finish disposition required for recovery; no raw question/answer. A pending incident has a durable new-admission denial predicate independent of whether the reader has terminally released. Source guards must check active exclusion in the same short physical-C ordering, not an eventually consistent cache. If existing reservations cannot express crash-recoverable Q&A lifetime, the [Owner decision](owner-decision-p19-reader-exclusion.md#exact-prospective-minimal-persistenceguard-delta-only-if-current-primitives-cannot-prove-it) specifies the bounded additive RAG reader state. Do not claim this is already implemented.

**Component ownership for prospective implementation:** Java `rag` owns authorization, reader record/terminal state, Q&A API, worker control and response emission; existing Vault/external-file owners and their source mutation SQL guards must enforce the active-reader exclusion; Python local inference is **untrusted for policy**, receives only authorized excerpts and cannot publish, authorize or revoke. PostgreSQL retains authoritative committed exclusion; no DB lock spans inference. Only the **minimum necessary prospective design delta** is Owner-approved under [P19-OD-01](owner-decision-p19-reader-exclusion.md); no additive migration/grant/SQL function or change to frozen mutation/worker contracts is **authorized for execution** yet. Codex must verify the exact changes and compatibility before a separately approved executable handoff. Wider-than-approved changes require another Owner decision. Do not invent function/table names as already installed.

## Canon/source selection contract (P19-PR-03)

**Current source limitation:** P18 stores opaque IDs, snapshot/revision identity, names and digest-bound link resolution. It does **not** establish an authoritative Ideaverse folder/canon classification. A basename (`CHỈ SỐ.md`), title, opaque digest, `source_name`, nearest filesystem root or LLM response is **not** a trusted `CORE/` classifier.

**Smallest Phase 19 solution — Owner-supplied explicit source-ID roster, not a new Ideaverse schema:**

1. At *manual* approval/import, the Owner/caller records a **versioned selection roster** from a known local tree or separately reviewed pinned Git snapshot. Each entry binds the existing RAG source ID, selected revision ID, approved relative path **as Owner-declared classification metadata**, group (`IDEAVERSE_CORE`, `IDEAVERSE_NONCORE` or `GENERIC`) and collection identity. Path labels are **not** filesystem authority; digest, basename or file path must never replace RAG source/revision IDs. An approved transclusion receives its own entry and own whole-file consent. Distinct paths/names keep distinct IDs. The caller retains the bounded roster for future requests (e.g. an explicit local selection file/client state); Phase 19 does **not** need to invent server-side folder discovery or a GitHub sync service. Roster must be refreshed/approved if source identity, selected revision or classification changes.
2. Java receives an **explicit allowlist of source IDs plus their expected selected revisions/group labels** for a canon-mode query and intersects them with live RAG authorization and `CURRENT` generation proof. Server MUST fail closed if the roster is absent, ambiguous, stale or exceeds bounds; it must **not** silently fall back to all Markdown. `IDEAVERSE_CANON` mode uses only listed `IDEAVERSE_CORE` IDs by default. Non-CORE is eligible only by an expressly selected noncanon mode and must be marked noncanonical in output. `GENERIC` mode, by contrast, defaults to all currently eligible approved Markdown; no universal CORE filtering.
3. **Evidence provenance is stricter than approved index dependencies.** An embedded child may be independently approved and correctly indexed, yet not selected as answer evidence. Before ranking, constructing model context, returning citations, even emitting result count/source aliases, the query requires **each actual contributing source ID and selected revision within every candidate evidence span** to be in the query's allowed set. In `IDEAVERSE_CANON`, a `CORE` parent containing a non-CORE child must not expose the child's content. Conversely, non-CORE parent / CORE child does not make parent content canonical. If a chunk mixes sources without a demonstrable span-by-source/locator separation, **discard the whole mixed chunk**; do not try to redact using model judgment. Parent/child indexing authorization is not a substitute for query selection.
4. The only trusted answers come from surviving eligible spans with citation keys resolved to actual source ID + selected immutable revision + generation + fragment/heading/offset where verified. Path/heading display is escaped/bounded and derived from approved roster/verified locators, not internal machine paths. Empty files and waypoint-only navigation are not factual source proof. Distinct same-named Markdown files never coalesce without source+revision identity.
5. Selection cardinality obeys bounded query limits, separate from P17's *per-indexing-job* 100-source cap. Do not assume 203 repo files are all imported/eligible/current. No query-time tree scan; default generic list arises from a bounded authorized PostgreSQL metadata query. The choice of how to persist/share the Owner-supplied roster is **not an implementation claim**; if durable server-managed groups become necessary, present the minimal additive schema/consent delta for separate Owner approval rather than silently creating a canon column.

**Proof cases:** CORE parent/non-CORE transcluded child (no child evidence); non-CORE parent/CORE child (not promoted by parent); two same-named files in different groups; deliberate noncanon opt-in; generic query using ordinary non-Ideaverse Markdown; stale or missing roster; revoked child and missing selected revision. All disallowed evidence is excluded **before** ranking as well as from response metadata.

## Whole-file consent versus source-level classification (P19-PR-02)

- For **external snapshot `.md`**: ADR-0022 N6/WF-1/WF-6 authorizes **the complete immutable original bytes**, including internal `private`, `nsfw`, hidden blocks/properties, comments and similar metadata, **only when that root/child has an individually valid whole-file consent bound to its exact S/R and currentness**. Internal markers alone do not trigger revocation, content redaction or extra per-field approval. A whole-file approval of parent does not approve child.
- Independently **deny source-level** missing/withdrawn approval, revoked/suspended/unknown source classification/consent/epoch/reset, corrupt or outdated generation, missing or unapproved dependency, forbidden scope/identity or failed integrity. This is never permission to ingest arbitrary secrets or unapproved sources. `FICTION/FILM` field-level Private/NSFW constraints remain in their own scope; they are not P19 data sources.
- Paired acceptance: (a) approved CURRENT Markdown with private-marked paragraph **must remain eligible evidence** when expressly in query selection; (b) same bytes in an UNAPPROVED/REVOKED external source must return nothing; (c) approved parent with unapproved child embed must not leak child. No override by `private:false` or implicit import of other files.
