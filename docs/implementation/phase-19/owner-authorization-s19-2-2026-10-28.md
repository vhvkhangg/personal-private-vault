## Exact approved S19-2 — bounded offline CPU grounded Markdown Q&A

**Name:** `P19-S19-2 — Offline Grounded Answer Generation and End-to-End Acceptance`.

The Owner approves a **minimal, authenticated, CPU-first, fully offline** question-answering path over the eligible Markdown evidence produced by **the already accepted S19-1 retrieval API**. Codex must create a complete, testable handoff fitting existing RAG modules and reuse decisions rather than designing a second retrieval, authorization, vector index or generic job framework.

1. **Grounded answer behavior.** Answer **only facts directly stated** in eligible `.md` evidence. Answer in Vietnamese by default, or in the requested supported language; preserve proper names/terms. Combine directly stated facts across authorized sources without inventing unstated conclusions or model-memory facts. Provide accurate source/file/heading/real-span citations and supporting excerpts where valid; forbid fabricated/unresolvable citations. Treat source excerpts, Markdown instructions and client history as untrusted data, not permissions or authoritative system instructions.
2. **Partial/conflict/unknown outcomes.** Answer independently supported subquestions while marking unsupported parts; explicitly present conflicting permitted sources **with both citations**, never silently choose a winner. Abstain when direct evidence does not support an answer. A nearby passage, an LLM assertion or a syntactically valid citation ID alone is not proof of material semantic support.
3. **Input, scope and small conversation.** Reuse existing S19-1 authenticated source selection and canon/noncanon roster semantics; generic Markdown scope must not become CORE-only. Client may supply a **small bounded number of recent turns** in each request; no persistent chat/session DB, personal memory or content-bearing operational logs. Respect explicit source IDs, revisions, transclusion/child consent, `CURRENT` generation and `WHOLE_FILE` marker semantics already accepted in S19-1/P17/P18.
4. **One offline generator and finite execution.** Evaluate **at most two** CPU-capable candidates using the same frozen tests, license and local resource evidence; pin the selected model/runtime/artifact checksums after demonstrated acceptance. Acquisition, if necessary, is a **deliberate one-time license/checksum-verified installation**, never inference-time download, remote AI/cloud inference or fallback to an unverified model. Use **one simplest adequate local model lifecycle**, bounded prompts/context/output/queue/wall-clock/CPU RAM and positive stop/disposal. Prioritize grounded accuracy over speed; over 30 seconds may be acceptable but unbounded execution is not. Use existing Windows/native process ownership, offline and resource safeguards. Preserve the accepted 384-dimensional multilingual retrieval embedding identity; no GPU requirement or speculative reranker/FTS.
5. **Security through actual emission.** Reuse S19-1 durable reader/inspection/incident fencing and source-dependent authorization through **retrieval, generation, validation and the actual non-streamed HTTP output**; retain accepted `C_A`/`C_I`/`C_E`/`C_D`/`C_RL`, quiescence, no-gap release and trusted-Java boundary. Use the approved nonblocking sender, HTTP DTO/root error envelope and source citation adapters rather than bypassing them. Model code is not a source-authorization authority; send it only eligible bounded evidence. Any stale/revoked/uncertain source, invalid citation, broken worker, exhausted resource, failed transport, cancel or unknown commit must fail closed without exposing unauthorized content. No long database transaction across inference or HTTP writes.
6. **Finite end-to-end evaluation.** Implement and run the [frozen 24-slot matrix](acceptance-matrix.md#frozen-proposed-qa-fixture-contract--24-slots-not-yet-executed): **M01–M16 all PASS**, **at least six E17–E24 PASS**, **zero unauthorized disclosure, fabricated source/citation/locator or unsupported material claim** in assessed answers. Freeze the 16 development/8 held-out **source-group-disjoint** fixtures/expected facts before comparing candidates, including **positive answerable Vietnamese, English and Han-script examples**; abstaining on an answerable mandatory case is **FAIL**. Keep deterministic citation/authorization tests distinct from sampled claim-by-claim semantic support checks; independent Codex reviewer assesses actual outputs, not an LLM judge or an invented human-signature ceremony. If both candidates fail, STOP and return a precise Owner decision; do not silently add a third model or weaken this rule.
7. **Actual runtime evidence.** Use only separately approved disposable/test-only import/index fixtures and existing test activation controls; never activate general external indexing or read live originals. Verify true Windows CPU runtime, cold/warm and queue-inclusive latency, peak RAM/headroom, offline restart, missing/mismatched artifacts, cancellation/deadline, process crash/unknown outcome, concurrent source/child denial, transclusion/canon/whole-file consent and non-leak before emission. Reuse unchanged independent S19-1 receipts honestly; run new/changed end-to-end guards and semantic evaluation. Choose proportionate, focused suites; no blanket full-backend test or redundant S19-3 requirement without demonstrated need.
