## Goal and exact implementation boundary

Authentication owns the complete login transaction and immutable verified Google issuer/sub binding to existing app_users.id=1. LINK needs PPV bearer sub=1 **plus freshly checked legacy password**; an access JWT obtained by refresh, email match or Drive slot never supplies that proof. LOGIN uses the linked Google subject only; no auto-user creation, unlink/rebind or raw-ID-token anonymous login.

The contract allows only named Authentication internals, the narrow internal SessionService issuance extraction, four new HTTP handlers, exact conditional security matchers, default-OFF settings, one **BOM-managed spring-boot-starter-oauth2-client**, additive **V28__google_signin_owner_transactions.sql**, explicit Portability exclusions and scoped tests/docs. Local BOM is Boot 4.1.1/Security 7.1.1; no version upgrade or new test/browser package. Google validation is private to the login transaction; PPV global HS256 decoder/issuer and legacy JWT/opaque-refresh/PIN/bootstrap/rotate/revoke behavior are preserved. No Drive internals/module edge or general auth refactor.

Three Authentication security relations only: ppv_owner_google_identities, ppv_google_login_attempts, ppv_google_handoff_tickets. Owner binding is insert-only under existing singleton lock; attempts hold hashed one-use state/binding/nonce/challenge and dedicated-key AES-GCM PKCE, including bounded failed LINK-password events. Tickets are stored as hashes and consumed **in the same PostgreSQL transaction** as canonical PPV refresh persistence/token issuance. Network I/O is outside locks; PROCESSING/restart never re-dispatches old code; concurrent/lost-reply ticket replay never issues a second pair. V1–V27 and existing table shapes remain unchanged.
