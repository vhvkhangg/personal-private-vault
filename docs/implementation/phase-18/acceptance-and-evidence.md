## Evidence budget and reporting semantics

- **One named [**P18-FINAL** integration gate](final-verification-gate.md) after focused convergence.** Run focused parser/OCR/held-out unit fixtures first, affected Python/Java changed-boundary tests second, then **exact pinned PowerShell bounded commands** in P18-FINAL once; link the R7/PostgreSQL/offline/model/RAM+VRAM receipts, not Maven alone. Long external commands use `scripts/run-bounded-command.py` (normal 1,200 s; 2,100 s only for approved full test suites and a host CLI that permits it). This is distinct from user indexing runtime budgets.
- Do not repeat the historical 420-job Phase 17 benchmark merely because it exists, unless touched behavior needs new measurements. Reuse truly unchanged prior evidence; explicit changed Windows NTFS R7/finalization paths **must** get new real tests.
- A receipt includes actual command exit, OS/hardware, model/engine/hash/version, elapsed time, file/fixture count, errors/skips, **peak RAM and peak VRAM separately**, CPU fallback and proof of clean/cancel outcomes. Avoid raw document text, full private file paths, sensitive prompts, secrets and arbitrary worker dumps.
- Existing job states are `COMPLETED` (at least one successful publication), `ABORTED` (zero), `CANCELLED`, and nonterminal `RECOVERY_REQUIRED` for unknown process/SQL outcome as defined by owner-approved D18-A; **do not invent** `SUCCESS` or `FAILED` DB states. `PARTIAL_SUCCESS` is a **summary/projection label**, not a unilateral DB enum addition. A historical successful file result is not automatically a `CURRENT` index.
- Security, source freshness, exact provenance, worker/process lifetime and DB COMMIT correctness are **non-negotiable**. Generic cloud/SaaS availability tests, every OCR vendor/model combination, dashboard, extra metrics dimensions, or LLM/rerank benchmarks are **not** implicit blockers.

## P17-N1 held-out quality and location acceptance

Before OCR/parser tuning, version sanitized **source-grouped development and independent held-out** sets (near-duplicates, all Obsidian transclusions and derived variants stay within one source group), label exact text/table/reading-order and per-format mandatory locators, record dataset/config/label hashes, check split disjointness and report **complete per-format/per-language denominators** including failures/skips/pending. Mandatory locator missing or fabricated is a material file failure; optional metadata only may warn. See the **binding** [source/locator oracle](held-out-quality-and-locators.md). Human labels/deterministic comparisons are sufficient; an LLM judge is **N/A** for P18.

## P18-FINAL named verification

The [executable final gate](final-verification-gate.md) names Python `ruff check`, `ruff format --check`, `mypy`, `pytest`, full Maven `clean verify` through the bounded runner, plus retained focused native Windows NTFS R7, actual PostgreSQL publication/role/recovery, held-out quality, offline model/runtime and separate system RAM/VRAM receipts. A command or required focused receipt not run / failed / nonzero is **not** a passing Phase 18 final gate. Phase 17's AUTH-CLOCK exception is **not automatically transferable**.

## Mandatory handoff feasibility questions for Codex

1. How can a **single existing** Phase 17 finalization commit atomically publish a subset of file generations while recording failures, without weakening whole-source closure reservation, stage-writer COMMIT fencing, purge or worker quiescence?
2. Which Java/SQL tables/status/DTOs currently exist? What is the smallest **proposed** additive migration/contract decision, and does it require a new ADR? No invented enum or table is accepted from this draft.
3. Can the targeted PDF/OCR stack actually cover required language/table/box cases with Windows Python 3.14-compatible native packages offline and within **16 GB RAM** / **8 GB VRAM**? What finite tests and thresholds establish feasibility?
4. Does the user-approved default live external-file capability remain disabled until **R7** evidence is independently accepted, and are Windows file handles held/guarded to actual Java physical COMMIT?
5. Which prior Phase 17 tests remain unchanged/creditable versus newly touched code requiring fresh tests? The 29-dimension review must yield proportional pass/finding/N/A/not-verified, not 29 new subsystems.
