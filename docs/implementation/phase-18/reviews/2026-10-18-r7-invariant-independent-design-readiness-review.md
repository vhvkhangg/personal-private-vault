## Approved invariant and late-link interpretation

ADR-0021 clause 3 and AC-07 require the **exact approved object/revision, authorized bytes and required metadata, reached through the approved path/root and ancestor/reparse relationships, continuously protected through trusted Java physical final C**. Clauses 2/6/8 and frozen P17-2/P17-3 additionally preserve consent, source/reset/field/authorization versions, exact child provenance, reservations, stop/seal and publication fences. These requirements remain intact.

The contract does **not explicitly require a universal ban on every transient alias** or that `nNumberOfLinks` always equals one. The existing count-one admission check is a valid conservative prerequisite: correct Win64 layout, unsigned reading, rejection on invalid/query failure, and denial cleanup remain credited. It establishes the sampled count at admission, not the absence of links before/after that query. A later name transition matters when it can alter a binding predicate; added aliases never become automatically approved sources or permitted worker paths.

**No protected-content bypass is reproduced.** Successful alias creation/replacement/unlink alone does not demonstrate one. Conversely, equal fixture hashes and blocked normal writers cannot certify the complete namespace/metadata invariant. The guard's original stronger regression remains genuinely failed: archived **17 tests, 16 pass, one fail, exit 1**, not rerun here. Its stale `removeDenial` placeholder remains a Low diagnostic defect; `created=true, removed=true` establishes the operations. Its cached-byte equality and conditional unexecuted write assertion cannot contradict the newer fresh observations. The test must remain unchanged until a separately accepted design and later authorization justify a precise replacement assertion; this review does not close or erase its failure.

## Acquisition authority — Critical residual FR18-1/2/8

Actual `WindowsNativeFileGuard.openAndGuard` checks filesystem/drive and named components, performs `toRealPath`, checks directory type, then `openWindowsNative` calls CreateFileW with ordinary target-following semantics. Only afterward does it query the leaf's attributes, count, volume/file ID and bytes. It accepts a Path, not the owner's approved object/root/ancestor authority tuple. No retained ancestor chain or comparison with preapproved native object identities closes that sequence.

The unresolved boundaries are **approval→acquisition** and **each relied-upon path/ancestor/reparse observation→the later native open**. A target reached after a component swap could be an ordinary file, with matching bytes, whose post-open ID describes what was reached rather than proving it was authorized. This is a concrete missing safety argument in source, **not a reproduced exploit**. D1 only installs its junction before checks begin. B9–B11 only exercise an already-acquired leaf. B12 proves a nonempty-directory restriction.

Volume/file IDs compare open objects but are not permanent historical consent identities; native IDs can be reused after deletion. A final-path string is an observation, not an ancestor lock. [BY_HANDLE_FILE_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-by_handle_file_information), [GetFinalPathNameByHandleW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew).

A future bounded design must identify the trusted approved-root anchor, exact object/ancestor comparisons, normalization/reparse rules, acquisition linearization point and protection covering all intervals in which those comparisons are relied upon. It must explain same-byte object/root replacement rejection and binding to the owner's observed approval, before bytes are sent. Merely pinning whichever object was opened, without proving its authorized root/path chain, fails that requirement. This review selects no native opening/traversal mechanism.

Post-open/path/hash/link-count rechecks can miss change→restore between observations and leave another interval before C. Changing to share mode zero or adding OPEN_REPARSE_POINT is not by itself an ancestor-binding proof. Notifications are observations, not continuous vetoes. Cached bytes, marker-C and eventual discovery cannot repair an unauthorized acquisition/publication. These shortcuts are excluded as complete designs.

## Continuous protection through physical C — still NOT_VERIFIED

The design must connect three existing boundaries, with explicit ownership/release paths:

1. **Native authority:** approved acquisition precedes consumption; retained object and required namespace/metadata protections cover guarded reads, transfer and the last validation through actual physical C. No arbitrary worker path reopening. Name/type/count/query failures deny before input. Explicitly account for pre-existing writers/maps, partial acquisition and handle/arena ownership, including confined-arena thread lifetime. Prior query-failure cleanup evidence is valid; CloseHandle failure is not proven successful release merely because an arena closes or a Java `closed` flag changes.
2. **Database authority:** Java retains source/consent/version/dependency authority and exact-union durable reservations, applying ADR-0021's source-first order and short transactions; no hashing/OCR/process wait under row locks. Native protection must continue while those short transactions are not held. Worker writes remain attempt-fenced through staging C. Positive task/tree stop and writer drain/seal precede trusted exact producer/output verification. One final writable Java PostgreSQL C installs all valid generations or none, records outcomes/terminal state and releases the exact reserved union atomically.
3. **Known failure and uncertainty:** known rollback publishes nothing and must reach the authorized safe abort/release path after quiescence. Unknown SQL/process outcomes remain nonterminal RECOVERY_REQUIRED with reservations/exclusivity retained and durable reconciliation; no blind finalization replay, expiry release or optimistic success. A live controller cannot drop necessary source protection while C is unresolved. Controller death cannot be described as surviving native protection: recovery must account for lost handles, actual SQL outcome, worker/writer safety and current source/history authority, suspending when that authority cannot be established. Release must have an explicit justified point on every path.

E1 permits a timely guarded validation followed by a late physical C; it does not waive continuous source/consent/privacy protection. A TransactionTemplate callback, marker transaction, final hash or release ACK is not proof of actual index C. The diagnostic intentionally exercised none of this publication lifecycle. **FR18-3 remains a separate Critical prerequisite:** the unchanged finalizer still derives `expectedOutput` from `DOCUMENT_V3:` plus input digest. The native probe does not establish exact producer, staged body/field/version/locator/output binding, and R7 alone cannot make that publication trustworthy.
