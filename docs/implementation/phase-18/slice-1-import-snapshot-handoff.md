## 2. MUST implement — Slice 1 only

1. **Explicit file intent and whole-file consent.** One authenticated manual user action identifies exactly one external regular file (or individual intents for a selected batch). No directory crawling, watcher, remote download, macro/script execution, or automatic transclusion opens. Treat server-local paths distinctly from files residing on a remote browser/client. Keep consent/source selection/authorization version and reset guards, explicit per-child authority and audit-safe errors. File content marked Private/NSFW/hidden within approved external files is part of the grant; frozen Vault field policies do not change.
2. **Bounded application-level acquisition G1.** Reject absent/unreadable/nonregular/unsupported paths, dangerous symlink/reparse traversal where practicable, unsupported filesystem cases and oversize sources. Copy into a unique application-managed temporary file with bounded streaming hash and byte count; compare practical before/after size, mtime and file identity when available; detect short write, read failure, observable change and cancellation. Verify the completed temp bytes, never mutate the owner original. Do **not** create native root-to-stream ABA proof, hostile same-user writer isolation, private DACL or Restricted Token requirements.
3. **App-managed ORIGINAL_BYTES R / G3.** Reuse store sealing and verification. Maintain distinct logical source **S**, revision **R**, and later index generation **G**; persist minimum **PENDING_R / selected-R reference** metadata and exact immutable original-byte manifest (source/revision ID, SHA-256, length and needed authority). No cross-source physical deduplication, overwrite or adoption of unregistered orphan. A sealed and verified pending R is eligible **for later authorized indexing**, not a selected/published `CURRENT` revision. **Do not advance sourceVersion, selected R pointer or active G during Slice 1:** ADR-0022 N4/N8 require changed-R selection, resulting sourceVersion and G publication together at future trusted `C_P` (Slice 3). PostgreSQL/file operations are not one atomic transaction: incomplete/uncertain copy/seal/DB operations stay nonselected, nonusable and safely recoverable; never silently mark success.
4. **Initial manual update foundation.** An approved changed-byte capture creates a **pending**, uniquely identified R bound to an expected selected-R/sourceVersion/consent CAS; it **does not select/promote** R until trusted `C_P` in Slice 3. Identical bytes may be classified internally as a **NO_CHANGE candidate** after verifying any existing selected R; do **not** expose a complete `NO_CHANGE` success or skip future indexing based on hash alone. Child-vector/pipeline eligibility and full guarded NO_CHANGE are deferred to Slice 4. Reindex must never reread the original; full reindex operation is also deferred.
5. **Lifecycle safety needed for exposed Slice 1 APIs.** Revocation, stale request, canceled copy, digest mismatch, missing/tampered pending or previously selected R and failed metadata write must deny use/selection; maintain durable enough state for safe restart reconciliation and bounded temp cleanup. Reuse existing source-first ordered guards, reservation/CAS and recovery; no new universal incident/transaction orchestration system. Do not enable indexing from snapshots until Slices 2–4 and independent acceptance.
6. **Compatibility.** Preserve Phase 17 **COMPLETE — FROZEN** behavior and tests, domain `FICTION`/`FILM` source semantics, existing `/api/v1/rag` contracts where possible, worker SQL `rag_worker` least privilege, existing v2/v3 staging and publication invariants. Maintain feature-gated/default-denied end-to-end external indexing; do not turn on `ppv.rag.test-scoped-execution` or an unrelated global runtime flag in production. New imported snapshots must not accidentally count as `CURRENT` published G.

## 4. Focused acceptance checklist (all required where relevant)

- [ ] Owner-selected TXT and binary files: captured bytes equal original sampled on completion, persisted SHA-256+length and manifest agree with verified R; original unchanged.
- [ ] File absent, directory, unsafe symlink/reparse, unwritable store, oversize input, altered-during-copy where detectable, canceled read, corrupt/temp/seal mismatch all fail closed, with no selected invalid R.
- [ ] Two different sources with identical bytes have distinct source/revision authorization and no cross-source physical deduplication; repeated exact input does not spuriously allocate/promote a new R without a guarded decision.
- [ ] Permission/whole-file consent and source-version/reset/CAS are tested; revoked/stale requests do not select or reactivate R.
- [ ] No-overwrite target collision, partial manifest, DB failure after copy, crash/restart orphan, cleanup failure and retry maintain deny-by-default and bounded recovery; no orphan auto-adoption or unintended sourceVersion/selected-R/G change.
- [ ] Two competing updates or cancel/revoke races cannot promote any pending R in Slice 1, create ambiguous pending authorization or bypass reservation/version checks. Existing domain and Phase 17 focused tests continue to pass.
- [ ] API produces no changed selected-R pointer/sourceVersion, false RAG `CURRENT`, finalized `NO_CHANGE` or published G; external indexing remains inactive until later slices; historical FR18-3 stays OPEN.
- [ ] Test records include command, environment (Windows and PostgreSQL where needed), passed/failed/skipped counts, test fixtures, exact code locations, residual risk and source HEAD; no fabricated Windows/OS anti-tamper guarantee.
