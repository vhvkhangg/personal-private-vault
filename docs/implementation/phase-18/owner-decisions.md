# Phase 18 — Owner decisions

## 2026-10-19 — New binding owner decision D12 (supersedes conflicting historical obligations)

**D12 — Proportionate single-user risk boundary: APPROVED.** Run the Python RAG worker under the same ordinary Windows account as Java; no Restricted Token/LPAC/AppContainer/Docker/WSL2 sandbox obligation. Simplify **G1 and G3 to ordinary application-level protection**: Java copies only expressly selected and authorized files, validates paths and observable copy changes, creates no-overwrite ORIGINAL_BYTES snapshots, hashes/verifies SHA-256 and length, checks correctness, denies detectable tampering, and safely reconciles crash/orphan/cleanup. The owner **accepts** that a malicious same-user Windows process may access unrelated readable files, modify snapshots or race NTFS checks. No OS-level anti-tamper guarantee. All RAG features, source consent and child approval, actual worker-output validation (FR18-3), SQL role restriction, trusted one-transaction publication, source guards/CAS and recovery remain required. **[ADR-0023](../../adr/0023-phase-18-application-level-snapshot-worker-trust.md) is the controlling amendment.**

The older D1–D11 decisions remain effective **only insofar as compatible with D12**. In particular, their 'protected', 'exact object/ancestor', 'restricted producer' and separate C_D/C_N/G1/G3 proof wording must now be interpreted under ADR-0023; do not demand discontinued Windows forensic/adversarial proofs or expand the decision into automatic implementation acceptance. Owner has not reviewed current source code through this documents-only package. Snapshot ingestion remains inactive; no finding auto-closed.

## Mandatory functionality retained

- Explicitly selected, individually approved `.md`/Obsidian, `.txt`, `.docx`, `.pdf` (native + scanned + mixed pages/tables), `.xlsx` and legacy `.xls`; no automatic directory crawling or per-directory blanket file consent.
- Obsidian frontmatter, headings/tags, wikilinks/aliases/heading and block links, approved transclusions, callouts and provenance. An embed target requires its **own current approval**; unapproved/failed/cyclic or escaped dependencies never become parent text; fail the parent where safe omission and sound attribution cannot be proved. Exclude unknown frontmatter fields and comments unless separately approved.
- Vietnamese with diacritics, English and Simplified/Traditional Chinese text/OCR as relevant; layout, reading order, tables, source locators and confidence/quality signaling. Do not execute macros, formulas, Dataview, JavaScript or remote links.
- Explicit consent, source/field allowlists, Private/NSFW exclusion, guarded file identity/NTFS R7, durable source-set reservations, one active job, one job-scoped worker, worker-role isolation, seal/fence/physical COMMIT, revocation and offline runtime inherited from frozen Phase 17.

## RAM is independently mandatory (not a synonym for VRAM)

Target desktop: **Windows 11; i5-9600K; 16 GB system RAM; RTX 2070 with 8 GB dedicated VRAM**. Phase 18 must **measure and report peak system RAM** (Windows working set/peak RSS of the indexing worker and any owned child processes; observe available host memory where practicable), **separately** from peak GPU VRAM. Measure wall time, CPU usage and temporary disk usage as relevant to bounded indexing. Memory protections must be finite, but do **not** invent fixed MB/page/batch quotas before representative local measurement; document chosen thresholds and fail-safe behavior prior to implementation acceptance. The agent **20-minute/35-minute command watchdog is not the user-indexing job timeout**.
