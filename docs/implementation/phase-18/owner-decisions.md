Minor nonmaterial warnings may pass with evidence. | A previous generation is usable only if it is still independently `CURRENT` after fresh version, approval, dependency and policy checks. Changed/revoked sources become `OUTDATED`/denied, not an automatic stale fallback. |
| **P18-03** | A single manually started multi-file job may **succeed for some files** and fail for others. File failures are isolated where safe. | The whole source/dependency closure must still be reserved and guarded; shared trust/worker/fencing failures abort the entire publish, and transitive Obsidian dependencies must not leak via other successful files. |
| **P18-04** | Only **one Java-owned finalization physical transaction at the end of the job** publishes all individually validated successful file generations or none. Failed files publish nothing new. | No early per-file commits/publish; do not grant the Python worker active-pointer/authorization rights. This is an explicit **proposed extension** of frozen Phase 17 atomic-finalization semantics; Codex must review its migration/state/contract impact and obtain explicit approval for the exact amendment before a handoff can implement it. |
| **P18-05A** | One **structure-first chunker** with narrowly scoped format rules, stable spans and structural metadata. Tune token budget/overlap against selected embedding tokenizer on representative samples. | No multiple competing chunking engines, LLM semantic chunking, generic strategy plugin platform, or hardcoded universal chunk size without data. |
| **P18-06A** | Adaptive PDF OCR at page/region level: extract reliable native text first; OCR only missing/low-quality areas; detect language when viable and accept explicit owner-selected language. | Support Vietnamese, English, Simplified/Traditional Chinese (Han-Viet is Vietnamese terminology, not a separate OCR alphabet). Do not OCR the entire PDF unconditionally. |
| **P18-07A** | At most **one targeted OCR retry** for potentially recoverable page/region quality failure, with a justified configuration adjustment. Material failure afterward fails the file. | No automatic retries for consent, security, source-version or worker-authority failures; no multiple-engine failover requirement. |
| **P18-08A** | Prefer a single selected embedding model on GPU; if GPU unavailable/OOM, allow **one controlled fallback to CPU using the same model and compatible vector space** with bounded batches/time/memory. | No model switching, mixing vector spaces, unbounded CPU loops, multi-model registry, or hot swapping. If worker trust is lost, fail the whole job. |
| **P18-09A** | Process large approved documents incrementally by page/section/row groups *where supported*, with finite input, expanded-content, page/row, chunk, RAM, VRAM, disk and time limits. Reject safely when limits or library behavior make processing unsafe. | Do not claim streaming for libraries that load full files in memory. No distributed jobs, page-level checkpoint engine or arbitrary unlimited-file promise. |
| **P18-10** | One lightweight structured indexing report: job counts/outcome, per-file status/reason/warnings/chunk count/OCR work, index generation and provenance version, elapsed time, GPU-to-CPU fallback and resource measurements. | Historical job outcome must be distinct from live `CURRENT`/`OUTDATED` validity. `PARTIAL_SUCCESS` is a **reporting concept**; do not invent a DB enum or change the frozen job state machine without Codex's compatibility proof and owner approval. No dashboard or unrelated telemetry platform. |

## Mandatory functionality retained

- Explicitly selected, individually approved `.md`/Obsidian, `.txt`, `.docx`, `.pdf` (native + scanned + mixed pages/tables), `.xlsx` and legacy `.xls`; no automatic directory crawling or per-directory blanket file consent.
- Obsidian frontmatter, headings/tags, wikilinks/aliases/heading and block links, approved transclusions, callouts and provenance. An embed target requires its **own current approval**; unapproved/failed/cyclic or escaped dependencies never become parent text; fail the parent where safe omission and sound attribution cannot be proved. Exclude unknown frontmatter fields and comments unless separately approved.
- Vietnamese with diacritics, English and Simplified/Traditional Chinese text/OCR as relevant; layout, reading order, tables, source locators and confidence/quality signaling. Do not execute macros, formulas, Dataview, JavaScript or remote links.
- Explicit consent, source/field allowlists, Private/NSFW exclusion, guarded file identity/NTFS R7, durable source-set reservations, one active job, one job-scoped worker, worker-role isolation, seal/fence/physical COMMIT, revocation and offline runtime inherited from frozen Phase 17.

## RAM is independently mandatory (not a synonym for VRAM)

Target desktop: **Windows 11; i5-9600K; 16 GB system RAM; RTX 2070 with 8 GB dedicated VRAM**. Phase 18 must **measure and report peak system RAM** (Windows working set/peak RSS of the indexing worker and any owned child processes; observe available host memory where practicable), **separately** from peak GPU VRAM. Measure wall time, CPU usage and temporary disk usage as relevant to bounded indexing. Memory protections must be finite, but do **not** invent fixed MB/page/batch quotas before representative local measurement; document chosen thresholds and fail-safe behavior prior to implementation acceptance. The agent **20-minute/35-minute command watchdog is not the user-indexing job timeout**.
