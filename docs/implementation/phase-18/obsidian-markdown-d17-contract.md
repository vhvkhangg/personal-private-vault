## Official syntax freeze and interpretation

Profile `ppv-obsidian-source-v1` freezes the official documentation retrieved on 2026-10-20:
[Obsidian Flavored Markdown](https://help.obsidian.md/obsidian-flavored-markdown),
[basic syntax](https://help.obsidian.md/syntax), [advanced syntax](https://help.obsidian.md/advanced-syntax),

[tags](https://help.obsidian.md/tags), [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/),
and [GFM 0.29-gfm](https://github.github.com/gfm/). Retrieval hashes/version receipts identify the
exact source snapshots; later online edits do not silently expand this profile.

The [source-freeze inventory](obsidian-markdown-d17-official-sources-2026-10-20.json) pins
Obsidian repository tree `cd6c9f3c7d5492bbbec94e8f403572b84eeb325b`, eight immutable blob IDs
and SHA-256 values, CommonMark examples and the GFM specification. Full downloaded snapshots stay
under `logs/phase18/s2-d17-markdown-2026-10-20/official/`; the development evidence script can retrieve
the pinned tree. This snapshot is specification input, not proof of full implementation conformity.

This is **structural source extraction**, not Obsidian rendering or plugin execution. Preserve
verbatim authored Markdown, including punctuation, whitespace, delimiters, comments and inert code,
alongside parsed structure. Source spans use original decoded Unicode character offsets and original
1-based lines; CRLF is not silently replaced in source text. Structured table cells have original
row/column/header/alignment and exact raw cell spans. Inline semantic nodes retain their containing
block/cell source locator; do not invent narrower inline character positions. Parent/child structures
and dependency edges retain their original source/revision. Rendering-generated HTML, diagram images,
formula answers and plugin results are not asserted to be authored source content.

Approved note content is a source tree: preserve the parent's authored embed marker and attach
child source units through explicit dependency edges, in authored embed order. The flattened output
lists a complete parent block before its child units; it does not claim an inline rendered DOM.
Large blocks define their complete source structure once; following slices reference that structure
ID and retain their own exact source text spans. Context locators remain original source locators,
not claims that a whole block/cell is wholly contained inside a small chunk. Properties use local
safe scalar handling (true/false booleans, decimal leading-zero integers, scientific notation,
date/datetime source data); YAML 1.1 yes/on/sexagesimal conversions must not invent property values.

Whole-file `.md` approval covers in-file properties/comments/hidden text under D12/ADR-0023.
The legacy field-filtered parser policy is unchanged. Necessary maintained CommonMark/GFM parsing
dependencies may be added with exact pins and lock/version verification; do not upgrade the frozen
interpreter, ML model, existing package versions or Phase 17 wire/authority contracts.

## Explicit whole-document failures

No partial-success fallback. An unresolved/unapproved note embed, unsupported binary/image/PDF/
audio/video/canvas embed, remote image/embed, conflicting supplied source revision, ambiguous or
missing selected anchor, invalid source mapping, malformed mandatory property/structure, resource
limit or cancellation rejects the **whole affected document** with a sanitized typed reason.
Ordinary links are inert authored references and do not grant dependency access. Code examples
containing an embed are inert text, not file authority.

Known dynamic query/template constructs whose displayed result requires execution (Dataview,
DataviewJS, core query/search result embeds, Tasks queries, Templater interpolation) are **not core
static Markdown output**: reject the entire document when encountered as executable directives.
Ordinary fenced JS/HTML/shell examples remain inert code. No community-plugin execution is supported,
and no claim is made that indexing a query's source reproduces its computed result. Unsupported
extensions necessary for complete content must be identified and fail explicitly; never relabel them
as a successful plain paragraph to claim full support.
